# 项目开发规则

## 一、技术选型
- **后端**：Golang 语言，采用 go-kratos 框架，基于大仓（Monorepo）模式进行微服务架构设计。
- **前端**：基于 Vben Admin（Vue3 + Vite + Ant Design Vue）作为后台管理系统开发框架，参考 [Vben 官方文档](https://doc.vben.pro/) 进行最佳实践。
- **数据库**：MySQL/PostgreSQL。
- **缓存**：Redis。
- **消息队列**：建议使用 Kafka/RabbitMQ。
- **API 通信**：主要采用 gRPC（服务间）与 RESTful（前后端）接口。

## 二、架构模式
- **后端采用大仓 Monorepo 管理**，各微服务模块独立开发、独立部署，统一依赖管理，目录结构清晰。
- **服务注册与发现**：建议使用 etcd/Consul。
- **配置中心**：建议使用 Apollo/Nacos。
- **统一网关**：所有外部 API 通过 API Gateway 统一接入。
- **前端采用模块化开发**，业务模块按功能拆分，组件复用。

## 三、前后端协作规范
- **接口定义**：所有接口需提前通过 OpenAPI/Swagger 或 protobuf 规范定义，前后端协同评审。
- **接口文档**：自动生成并及时维护，便于前端调用和测试。
- **接口返回格式**：统一采用标准响应结构（如 code、msg、data）。
- **错误码管理**：后端集中管理错误码，前端根据错误码做友好提示。
- **权限与认证**：采用 JWT/OAuth2 统一认证，前端需配合 Token 管理与刷新。

## 四、Vben 前端开发约定
- **组件复用**：优先使用 Vben Admin 内置组件，二次开发需遵循组件化、可配置、可复用原则。
- **样式规范**：统一使用 Less/Sass，遵循 BEM 命名规范，支持主题切换。
- **路由与权限**：路由配置与后端权限体系联动，动态菜单根据用户权限生成。
- **国际化**：所有用户可见文本需支持 i18n 国际化。
- **代码风格**：遵循 ESLint + Prettier 统一代码风格，提交前自动格式化。
- **单元测试**：核心组件和工具函数需编写单元测试。

## 五、后端开发约定
- **目录结构**：遵循 go-kratos 官方推荐结构，业务逻辑与基础设施解耦。
- **配置管理**：所有配置集中管理，支持多环境切换。
- **日志规范**：统一日志格式，关键操作需详细记录，便于追踪与排查。
- **错误处理**：所有错误需封装为标准错误类型，返回有意义的错误信息。
- **单元测试**：核心业务逻辑必须覆盖单元测试，测试用例需覆盖边界场景。
- **接口幂等性**：关键接口需保证幂等性，防止重复操作。

## 六、CI/CD 与版本控制
- **分支管理**：采用 Git Flow 或 trunk-based 流程，feature/bugfix/release 分支规范。
- **提交规范**：遵循 Conventional Commits 语义化提交。
- **自动化部署**：集成 CI/CD 工具（如 GitHub Actions、Jenkins），自动化测试、构建与部署。
- **版本管理**：重要功能需记录更新日志，遵循语义化版本规范。

## 七、文档与设计
- **API 文档**：自动生成并随代码更新。
- **架构设计文档**：重要设计决策需记录，便于团队协作与知识传承。
- **使用说明**：为主要模块和工具提供详细使用说明。

## 八、性能与安全
- **性能优化**：关键路径需关注性能瓶颈，定期进行性能分析与优化。
- **安全加固**：接口需防范常见安全风险（如 SQL 注入、XSS、CSRF），敏感信息加密存储。

## 九、其他约定
- **第三方依赖**：优先选用社区活跃、维护良好的依赖库，定期升级。
- **代码评审**：所有合并需经过团队成员评审，确保代码质量。
- **异常监控**：集成监控与告警系统，及时发现并处理异常。
