# 项目开发底座架构文档

本目录只放当前生效的项目开发底座架构决策、服务边界、冻结清单和拆分条件。项目服务定义放在 `docs/services`；产品需求、字段、验收标准放在 `docs/product`；代码规范放在 `docs/vibe-coding`。

## 当前文档

- `00-后端底座架构决策.md`：项目开发底座后端大仓策略、底座管理后台基础服务、服务边界、冻结清单和执行守门规则。
- `01-多租户菜单权限组实施计划.md`：底座管理后台多租户业务套餐、租户绑定套餐和角色二次授权的实施依据。
- `02-多租户底座治理能力开发计划.md`：底座治理能力路线图，以及数据字典、操作审计首期实施边界。
- `03-多租户认证与会话安全设计.md`：登录安全日志、多设备会话、Token 轮换和强制下线设计。
- `04-多租户生命周期与开通编排.md`：租户状态机、原子开通事务、初始化安全边界和验收标准。
- `05-业务套餐版本化设计.md`：套餐不可变版本、发布回滚、租户固定版本和缓存一致性设计。
- `06-平台身份与租户身份安全边界.md`：平台控制面身份、租户管理员生命周期、令牌声明、Casbin 策略拆分和跨租户操作守门规则。
- `07-多租户参数配置中心设计.md`：平台参数定义、租户覆盖、类型约束、缓存一致性和敏感配置边界。
- `08-统一异步任务中心设计.md`：持久化任务、幂等入队、租约抢占、重试退避、平台监控和扩展边界。
- `09-租户内数据权限设计.md`：角色数据范围、用户主部门、部门层级一致性和受控资源接入规则。
- `10-平台底座生产化优化实施计划.md`：围绕授权闭环、开通一致性、缓存可靠性、生产门禁和质量验证的分阶段实施依据。
- `11-项目服务模块接入规范.md`：新底座模块和业务项目服务接入时必须满足的后端、前端、权限、数据、测试和文档清单。
- `12-架构决策记录索引.md`：当前生效 ADR，固化平台服务边界、租户套餐优先、菜单权限缓存和前端 API 类型策略。

## 使用规则

- 新增业务模块前，先读取本目录，确认默认落点和禁止事项。
- 架构决策只能在本目录更新，不要散写到产品需求或旧归档文档中。
- `docs/archive` 中的历史架构描述只作参考，和本目录冲突时以本目录为准。
- 只有出现独立部署、独立扩缩容、独立公共 API、独立数据生命周期或清晰业务域边界时，才允许提出新 Kratos service。
- 新增模块必须先通过 `11-项目服务模块接入规范.md` 的清单评审；缺少契约、权限、租户边界、测试或 Mock 的模块不得进入默认迭代。

## 当前冻结结论

- `backend-service/app/platform/admin` 当前升级为项目开发底座管理后台基础服务，目标是脱离具体业务。
- `backend-service/app/ai/service` 是项目开发底座 AI/chat 能力服务。
- `backend-service/app/version/service` 保留为已存在雏形，当前冻结，不作为迭代 1/2 的新增业务落点。
- 业务服务（版本管理、Release、灰度、下载页、反馈、协议、推送等）不再继续进入 `backend-service/app/platform/admin`。
- 业务服务需要独立服务边界；`version/service` 是否升级为正式服务仍需复审。
