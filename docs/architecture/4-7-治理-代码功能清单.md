# 代码功能清单

> 最后更新: 2026-07-24
> 生成方式: 代码扫描 + 人工确认
> 维护规则: `[x]` 已完成 | `[~]` 进行中 | `[ ]` 待开发 | `[.]` 暂缓
>
> 此清单同时支持**人工维护**和**系统自动维护**：
> - 人工：直接编辑状态标记 `[x]`/`[~]`/`[ ]`/`[.]` 和优先级 P0-P3
> - 自动：`make checklist-scan` 扫描代码中的 Proto RPC、Ent Schema、Service/API 文件，更新 `<!-- auto-source -->` 注释中的源文件路径
> - 冲突处理：人工标记优先级高于自动扫描，自动扫描不覆盖人工修改的状态和优先级

---

## 使用说明

### 开发前流程

```
1. 打开本清单 → 确认目标功能是否存在
2. 不存在 → 在对应模块下追加新行（格式见模板）
3. 存在但范围不对 → 直接编辑功能描述
4. 确认后 → 将状态改为 [~]（进行中）
5. 开发完成 → 将状态改为 [x]（已完成）
```

### 功能行格式

```markdown
| [x] | P0 | 功能名称 | 功能描述 | `proto/file.proto` `ent/schema.go` `service.go` |
```

- **状态**: `[x]` 已完成 / `[~]` 进行中 / `[ ]` 待开发 / `[.]` 暂缓
- **优先级**: P0(必须) / P1(当前) / P2(下一迭代) / P3(远期)
- **功能名称**: 简短标识
- **功能描述**: 一句话说明
- **源码追溯** `<!-- auto-source -->`: 自动扫描填充的代码文件路径，`*` 开头表示该行由代码扫描自动生成

### 自动扫描规则

运行 `cd backend-service && go run cmd/checklist/main.go` 或等价的 grep 脚本：
1. 扫描 `proto/` → 提取所有 RPC 定义 → 匹配已有行或追加新行
2. 扫描 `internal/data/ent/schema/` → 提取 Ent Schema → 匹配已有行
3. 扫描 `internal/service/` → 提取 Service 实现 → 匹配已有行
4. 扫描前端 `views/` `api/` `router/` → 提取页面和 API → 匹配已有行
5. 新发现的功能追加为 `[ ] | P2` 行，带 `<!-- auto-generated -->` 标记
6. 代码已删除但清单中存在的行标记为 `<!-- orphan -->`，不自动删除
