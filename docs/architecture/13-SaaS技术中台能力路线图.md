# SaaS 技术中台能力路线图

日期：2026-07-18
状态：持续维护
定位：项目开发底座的中长期能力总控清单

## 1. 目标

本路线图用于持续推进项目开发底座从“多租户管理后台”升级为“可复用、可验证、可扩展的 SaaS 技术中台”。

后续每轮开发必须回到本文档更新状态，确保可以断点续接：

- 当前已完成能力；
- 下一批优先级；
- 每个能力的验收标准；
- 依赖关系和风险；
- 实施证据和提交记录。

本文档是总控路线图。细节设计仍放在对应专题文档，例如：

- `10-平台底座生产化优化实施计划.md`
- `11-P3通用底座能力设计.md`
- `11-项目服务模块接入规范.md`
- `12-架构决策记录索引.md`

## 2. 总体原则

- 底座能力优先于业务功能。通知、文件、Webhook、计量、安全、可观测等横向能力稳定后，再承载更多业务模块。
- 平台控制面和租户数据面必须分离。平台管理员管理全局配置，普通租户只能使用当前租户能力。
- 菜单隐藏不是安全边界。所有接口必须进入后端授权和租户隔离。
- 能力必须可 Mock、可迁移、可测试、可观测。缺少 Mock 数据、权限码、测试和验证入口的模块不得视为完成。
- 新能力默认落在 `backend-service/app/platform/admin`，只有出现独立部署、独立扩缩容、独立生命周期或清晰业务域边界时，才考虑拆分 Kratos service。
- 前端底座管理页默认落在 `frontend-service/apps/web-antd-admin`，并遵循 Vben 管理后台模式。

## 3. 能力分层

### 3.1 平台控制面

目标：平台方统一管理租户、套餐、权限、配置、审计和底座资源。

已具备：

- 租户管理。
- 租户业务套餐和权限组。
- 菜单权限、接口权限、角色授权。
- 用户、部门、岗位。
- 参数配置、字典管理。
- 操作日志、登录日志。
- 异步任务。
- 存储渠道管理。
- 文件中心。

待补齐：

- 平台级系统设置中心。
- 租户生命周期增强：试用、续费、冻结、注销、恢复。
- 租户开通模板：套餐、默认角色、默认菜单、默认配置一键初始化。
- 平台公告和版本变更公告。
- 平台审计视图：租户、套餐、权限、存储渠道等关键配置变更记录。

### 3.2 权限与安全中心

目标：形成可验证的 SaaS 安全基座。

已具备：

- 多租户隔离。
- 平台控制面和租户数据面权限分类。
- 菜单权限、接口权限和租户套餐能力控制。
- 角色授权保存、回显和缓存刷新。
- 普通租户角色数据库授权路径。

待补齐：

- 数据权限策略中心：全部、本部门、本部门及下级、本人、自定义范围。
- API 权限策略管理页面。
- 登录安全策略：密码复杂度、失败锁定、登录有效期。
- MFA/二次验证预留。
- Session 管理：在线用户、强制下线、设备列表。
- IP 白名单和黑名单。
- 敏感操作二次确认。
- Secret 管理：S3、Webhook、邮件、短信等密钥统一托管。
- 安全审计报表。

### 3.3 能力包与计量中心

目标：将套餐从菜单集合升级为真正的 SaaS 能力包。

已具备：

- 租户业务套餐版本化。
- 菜单、接口权限、功能开关、资源额度。
- 当前租户资源额度查询、检查、占用、释放。
- 项目资源额度接入。

待补齐：

- 套餐版本发布审批。
- 套餐变更影响分析。
- 租户用量统计：文件数、存储容量、项目数、用户数、API 调用数。
- 额度预警。
- 超额策略：拒绝、软限制、平台审批扩容。
- 计费和订阅模型预留。

### 3.4 文件与存储中心

目标：统一处理租户文件、业务附件、导入导出文件和公开资源。

已具备：

- 文件元数据。
- S3-compatible 存储。
- 本地存储。
- 存储渠道管理。
- 默认存储渠道。
- 文件中心权限、Mock 数据和后台入口。

待补齐：

- 文件上传前检查 `files`、`storage.bytes` 额度。
- 上传确认后占用文件数和存储容量额度。
- 删除文件后释放额度。
- 文件访问日志。
- 文件详情和访问记录页面。
- 文件分类、标签和业务绑定。
- Multipart Upload。
- 私有文件下载代理。
- CDN 私有签名。
- 病毒扫描和内容安全扫描预留。
- 生命周期策略：过期清理、归档、回收站。

### 3.5 通知中心

目标：为系统公告、告警、审批、用户消息和业务通知提供统一能力。

待建设：

- 通知模板。
- 通知渠道：站内信、邮件、短信、Webhook。
- 通知任务。
- 通知记录。
- 失败重试。
- 用户通知偏好。
- 租户通知配置。
- 平台通知公告。

第一轮 MVP：

- 站内信。
- 通知模板。
- 异步发送任务。
- 通知已读和未读。
- 管理后台通知记录。

### 3.6 Webhook 与事件中心

目标：形成 SaaS 对外开放能力，不让业务模块直接投递外部 HTTP。

待建设：

- 事件类型注册。
- 租户 Webhook 订阅。
- Webhook 密钥。
- 签名算法。
- 投递任务。
- 投递记录。
- 失败重试。
- 死信队列。
- 人工重放。
- 事件审计。

首批事件建议：

- 租户创建。
- 租户套餐变更。
- 用户创建。
- 角色权限变更。
- 文件上传完成。
- 资源额度超限。
- 异步任务失败。

### 3.7 可观测与运维中心

目标：让底座可部署、可巡检、可告警、可定位问题。

已具备：

- 异步任务健康。
- 授权缓存健康。
- 资源额度 readiness 指标。
- 根仓库真实链路验证脚本。

待补齐：

- 服务健康总览。
- Redis/MySQL 连接健康。
- 缓存命中率。
- API 慢请求日志。
- 错误日志聚合。
- 定时任务和异步任务 dashboard。
- 系统告警规则。
- 管理后台运行状态页。
- 配置变更审计。
- 数据库迁移状态查看。
- Mock/Seed 数据版本记录。

### 3.8 开发者与模块接入中心

目标：让项目底座不仅能运行，也能持续承载新模块。

已具备：

- 模块接入规范文档。
- Proto/Buf 生成流程规范。
- 服务级 Makefile 规范。
- 后端和前端基础质量门禁。

待补齐：

- 模块注册中心：模块编码、名称、菜单、权限、资源额度、功能开关。
- 模块接入规范后台入口。
- API 文档入口。
- 菜单权限码生成规范。
- Seed/Mock 数据规范。
- 新模块检查清单后台化。
- 后端测试覆盖率门禁可视化。
- 前端类型检查和构建门禁可视化。
- 一键验收脚本执行记录。

## 5. 下一轮执行计划

### 阶段一：文件中心闭环

目标：

- 文件上传、确认、删除与资源额度闭环。
- 文件访问有审计记录。
- 管理后台可查看文件详情和访问记录。

任务：

- 上传会话创建前检查 `files` 和 `storage.bytes` 额度。
- 上传确认后占用 `files` 和 `storage.bytes`。
- 删除文件后释放 `files` 和 `storage.bytes`。
- 额度操作使用业务幂等键，避免重试误占用或误释放。
- 新增 `file_access_logs` 表和查询接口。
- 下载、预览、删除写入访问日志。
- 管理后台文件中心增加详情抽屉和访问记录区。
- Mock 数据增加访问日志样例。
- 补充跨租户访问日志隔离测试。

验收：

- 超过文件数或存储容量额度时，上传会话创建被拒绝。
- 同一上传确认请求重复提交不会重复占用额度。
- 删除已确认文件后额度释放，重复删除不会重复释放。
- 普通租户只能查看当前租户文件访问日志。
- 平台管理员可按租户查看文件访问日志。
- 后端重点包测试和真实 Mock 自检通过。
- 管理后台类型检查和构建通过。

### 阶段二：通知中心 MVP

目标：

- 支撑站内信、系统公告和异步通知。

任务：

- 定义通知模板、通知消息、通知记录契约。
- 新增通知模板、通知消息 Ent schema。
- 复用异步任务发送通知。
- 支持已读、未读、批量已读。
- 管理后台增加通知模板和通知记录页面。
- 租户侧提供当前用户通知列表和未读数。
- Mock 数据增加通知模板、通知消息和未读样例。

验收：

- 平台管理员可创建和启停通知模板。
- 系统可通过异步任务生成站内信。
- 当前用户只能读取自己的通知。
- 已读状态可回显，批量已读幂等。
- 异步发送失败可重试并可在任务中心观察。

### 阶段三：Webhook 与事件中心 MVP

目标：

- 对外提供租户级事件订阅、签名投递、失败重试和死信重放。

任务：

- 定义事件类型、Webhook 订阅、投递记录契约。
- 新增事件类型、订阅、投递记录 Ent schema。
- 实现签名算法和密钥管理。
- 投递任务接入异步任务。
- 支持失败重试、死信、人工重放。
- 管理后台增加 Webhook 订阅和投递记录页面。
- 首批接入文件上传完成、资源额度超限、异步任务失败事件。

验收：

- 租户只能管理当前租户 Webhook 订阅。
- 投递请求携带事件 ID、时间戳和签名。
- 非 2xx 或网络失败进入重试。
- 超过最大重试进入死信。
- 人工重放不会改变原始事件事实。

### 阶段四：运维与审计增强

目标：

- 形成平台运行态总览和关键配置变更追踪。

任务：

- 系统健康总览接口和页面。
- MySQL、Redis、授权缓存、资源额度、异步任务健康聚合。
- API 慢请求和错误日志记录。
- 配置变更审计。
- 存储渠道变更审计。
- 套餐变更影响分析。
- Mock/Seed 数据版本记录。

验收：

- 管理后台可查看服务健康总览。
- 关键配置变更可追溯到操作者、时间、前后值。
- 套餐变更前可看到受影响租户数量。
- 运维健康接口可被脚本和后台复用。

## 6. 断点续接规则

每次继续任务前，按顺序读取：

1. `docs/architecture/README.md`
2. 本文档
3. 当前阶段对应专题文档
4. 最近一次提交记录和 git 状态

每次完成任务后，必须更新：

- 本文档的优先级队列状态；
- 当前阶段的任务和验收结果；
- 对应专题设计文档；
- `10-平台底座生产化优化实施计划.md` 的实施记录；
- 必要时更新 `12-架构决策记录索引.md`。

状态枚举：

- `待启动`：已定义，未开始编码。
- `进行中`：已开始实现，但未完成验收。
- `已实现`：代码完成，尚未完成真实链路验证。
- `已验证`：自动化测试、Mock 或真实链路验证通过。
- `冻结`：暂不推进，需等待架构或业务确认。

- 文件访问日志、文件详情和访问记录后台尚未完成。

- 可观测和开发者中心仍以文档规范为主，尚未后台化。
