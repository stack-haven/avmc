# 多租户生命周期与开通编排

日期：2026-06-29  
状态：实施中  
范围：项目开发底座平台控制面

## 1. 目标

租户开通不是单表创建，而是一个不可分割的平台控制面操作。首期必须在同一数据库事务内完成：

1. 创建租户。
2. 绑定业务套餐。
3. 创建租户根部门。
4. 创建租户管理员角色，并将套餐有效菜单授予该角色。
5. 创建初始管理员并绑定管理员角色。
6. 将租户置为可用状态。

任一步骤失败时全部回滚，不允许产生缺少管理员、角色或组织的半成品租户。

## 2. 生命周期状态

租户使用独立的 `lifecycle_status` 表达业务生命周期：

- `PENDING`：待开通，仅用于编排过程或异常恢复，不允许登录。
- `ACTIVE`：正常服务，允许登录和刷新会话。
- `SUSPENDED`：人工暂停，不允许登录，已有会话全部失效。
- `EXPIRED`：服务到期，不允许登录，已有会话全部失效。
- `CANCELLED`：已注销，不允许恢复为正常租户，已有会话全部失效。

允许的状态迁移：

| 当前状态 | 允许迁移 |
| --- | --- |
| `PENDING` | `ACTIVE`、`CANCELLED` |
| `ACTIVE` | `SUSPENDED`、`EXPIRED`、`CANCELLED` |
| `SUSPENDED` | `ACTIVE`、`EXPIRED`、`CANCELLED` |
| `EXPIRED` | `ACTIVE`、`CANCELLED` |
| `CANCELLED` | 无 |

现有通用 `status` 字段在过渡期保留：

- `ACTIVE` 同步为 `STATUS_ENABLED`。
- 其他生命周期状态同步为 `STATUS_DISABLED`。
- 认证以生命周期状态为准，并兼容迁移前只有 `status` 的数据。

## 3. 开通契约

创建租户请求由三部分组成：

- 租户基本信息：名称、编码、有效期、备注。
- 业务套餐：一个或多个菜单权限组。
- 初始管理员：用户名、真实姓名、邮箱和初始密码。

约束：

- 初始管理员用户名、邮箱遵循现有用户唯一性规则。
- 初始密码使用现有密码强度规则，并在进入 data 层前完成哈希。
- 明文密码不得写入日志、审计摘要或响应。
- 至少绑定一个有效业务套餐，防止创建不可操作的租户。
- 管理员角色菜单取所有已绑定套餐有效菜单的并集。

## 4. 一致性与缓存

- 数据库提交成功后才刷新租户套餐菜单缓存版本。
- 套餐菜单变更继续按受影响租户批量提升缓存版本。
- 开通事务失败不得刷新缓存。
- 状态离开 `ACTIVE` 后立即撤销租户全部会话。
- 状态恢复为 `ACTIVE` 不恢复旧会话，用户必须重新登录。

## 5. 安全边界

- 开通接口属于平台控制面权限，只允许具备租户创建权限的身份调用。
- 初始化数据使用系统数据库上下文写入指定新租户，但目标 `tenant_id` 必须由开通事务生成，不能接受客户端传入。
- 租户管理员角色只能获得套餐有效菜单，不得自动获得套餐外平台控制面菜单。
- 注销采用不可逆生命周期状态；物理清理和数据保留策略在隐私治理阶段单独实现。

## 6. 验收标准

- 正常开通后，可使用初始管理员登录并看到套餐内菜单。
- 租户、套餐绑定、根部门、管理员角色和管理员用户同时存在。
- 套餐无效、用户名冲突或任一步骤失败时，数据库中不存在该租户的残留数据。
- 暂停、到期和注销后，已有会话失效且不能重新登录或刷新令牌。
- 恢复正常后只能重新登录，旧会话仍然无效。
- 现有租户迁移后默认为 `ACTIVE`，原停用租户迁移为 `SUSPENDED`。
