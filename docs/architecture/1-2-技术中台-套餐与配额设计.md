## 一、套餐优先模型

```mermaid
flowchart TB
    Platform["平台方"] -->|"① 维护全局菜单池"| MenuPool["全局菜单池"]
    Platform -->|"② 定义套餐版本"| Package["业务套餐<br/>菜单权限组 + API权限 + 功能开关 + 资源配额"]
    Platform -->|"③ 绑租户"| Tenant["租户"]
    Tenant -->|"④ 套餐范围"| TenantAdmin["租户管理员"]
    TenantAdmin -->|"⑤ 角色授权(子集)"| Role["角色"]
    Role -->|"⑥ 用户分配"| User["用户"]
    User -->|"⑦ 有效权限"| Effective["有效菜单 ∩ 有效API权限"]
```

**有效权限公式：**

```
用户最终权限 = 全局菜单(启用) ∩ 租户套餐菜单 ∩ 用户角色授权菜单
              ∩ 租户状态(ACTIVE) ∩ 用户状态(启用) ∩ 角色状态(启用)
```

## 二、套餐版本化

```mermaid
stateDiagram-v2
    [*] --> V1: 创建套餐 → 自动发布 V1

    V1 --> V2: 编辑菜单 → 自动发布 V2
    V2 --> V3: 编辑菜单 → 自动发布 V3

    V3 --> V3_ROLLBACK: 回滚到 V1
    V3_ROLLBACK --> V4: 复制 V1 → 发布 V4

    state 租户视角 {
        AutoUpgrade: 跟随最新 (auto_upgrade=true)
        Pinned: 固定版本 (auto_upgrade=false)
    }
```

### 版本规则

- 每个套餐版本是**不可变的菜单+权限快照**
- 编辑套餐菜单 → 自动发布新版本号
- 编辑元数据（名称/描述）→ 不产生新版本
- 回滚 = 复制历史版本 + 更高版本号发布（保留审计链）
- 租户可固定版本或跟随最新

## 四、资源配额模型

```mermaid
flowchart TB
    Define["定义配额维度<br/>参数定义: tenant_resource_quota"] --> Bind["套餐绑定配额<br/>指定每维度上限值"]
    Bind --> TenantBind["租户绑定套餐"]
    TenantBind --> Check["业务操作前检查<br/>POST /usage/check"]
    Check -->|"余量充足"| Consume["执行+上报用量<br/>POST /usage/report"]
    Check -->|"超额(软限制)"| Warn["允许但记录超额<br/>返回超额费用估算"]
    Check -->|"超额(硬限制)"| Deny["403 QUOTA_EXCEEDED<br/>拒绝操作"]

    Consume --> Release["资源释放<br/>删除时 Release 额度"]
```

### 配额操作幂等

```
QuotaOperation {
    idempotency_key  "业务幂等键 (scope+key+fingerprint)"
    action           "consume|release"
    amount           "操作数量"
}
```

- 同一幂等键重复请求 → 返回首次结果（不重复扣减）
- 上传确认后 occupy，删除后 release
- 所有配额操作有独立日志

## 五、缓存策略

```mermaid
flowchart TB
    Request["查询有效权限"] --> Cache{"Redis 命中?"}
    Cache -->|"命中 + 版本匹配"| Return["返回缓存"]
    Cache -->|"未命中|版本过期"| DB["查询数据库"]
    DB --> Build["构建有效权限"]
    Build --> SetCache["写入 Redis<br/>key = menu:<version>:<tenant>:<user>"]
    SetCache --> Return

    Invalidate["套餐/角色变更"] --> IncrVersion["递增版本号"]
    IncrVersion --> AsyncTask["异步任务: 刷新缓存"]
```

**核心原则：缓存是优化而非授权事实来源。缓存不可用时降级到数据库查询。**

## 六、Feature Flag 生命周期

> 从前端 `FeatureGate` / `usePlatformCapability` / `platformCapabilityStore` 实际实现提炼。

### 能力获取

```text
GET /admin/v1/current-tenant/capabilities
→ {
    apiPermissions: ["tenant.user.create", ...],
    featureFlags: { "new_dashboard": true, "export_excel": false },
    resourceQuotas: { "files": 100, "storage.bytes": 1073741824 }
  }
```

聚合规则：API 权限并集、功能开关 OR（true 优先）、资源配额每 key 取最大值。

### 前端消费

```typescript
// usePlatformCapability 模式
const { hasFeature, matchFeatureFlags, hasApiPermission } = usePlatformCapability()

// FeatureGate 组件
<FeatureGate feature="new_dashboard">
  <NewDashboard />
</FeatureGate>

// 多条件 (all=全部满足 any=任一满足)
matchFeatureFlags(['export_excel', 'admin_mode'], 'any')
```

### 四阶段生命周期

```mermaid
stateDiagram-v2
    [*] --> CREATED: 套餐版本中定义新 Flag

    CREATED --> ROLLOUT: 发布到指定租户<br/>(auto_upgrade=true 自动获取)

    ROLLOUT --> GA: 验证通过<br/>标记为默认开启

    ROLLOUT --> ROLLED_BACK: 发现问题<br/>回滚套餐版本

    GA --> DEPRECATED: 功能稳定后<br/>标记为待清理

    DEPRECATED --> REMOVED: 代码清理<br/>从套餐定义中移除

    ROLLED_BACK --> CREATED: 修复后重新发布
```

### 操作规则

| 阶段 | 操作 | 约束 |
|------|------|------|
| **创建** | 在 `MenuPermissionGroupVersion` 的 `feature_flags` 中新增 key | key 命名: `snake_case`，如 `new_dashboard` |
| **灰度** | 发布新套餐版本，租户 `auto_upgrade=true` 自动获取 | 不在代码中硬编码租户白名单 |
| **全量** | 默认值设为 `true`，所有新建租户默认开启 | 不影响已绑定固定版本的租户 |
| **废弃** | 代码中标记 `@deprecated`，前端移除 FeatureGate | 保留至少一个大版本周期在定义中 |
| **清理** | 从套餐版本定义的 `feature_flags` 中删除 | 确认所有租户已迁移到新版本 |

### 代码约定

- Feature Flag **不能替代权限校验** — 它是 UI 层开关，后端必须独立授权
- Flag key 不包含租户特定信息 — 不是 `tenant_123_feature_x`
- 同一 Flag 不在多处硬编码判断 — 统一通过 `hasFeature()` 消费
