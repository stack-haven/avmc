## 一、租户模型

### 核心实体

```mermaid
erDiagram
    TENANT ||--o{ TENANT_PRODUCT : "开通产品"
    TENANT ||--o{ TENANT_USER : "拥有成员"
    TENANT ||--o{ TENANT_PERMISSION_GROUP : "绑定套餐"
    TENANT_USER }o--|| USER : "关联用户"

    TENANT {
        string tenant_id PK "租户唯一标识"
        string name "企业名称"
        string code "租户编码(唯一)"
        string lifecycle_status "PENDING|ACTIVE|SUSPENDED|EXPIRED|CANCELLED"
        bool is_platform "是否平台租户(内部控制)"
        jsonb settings "租户配置"
        timestamp created_at "创建时间"
    }

    TENANT_PRODUCT {
        string tenant_id FK "所属租户"
        string product_code FK "产品编码"
        string plan_id "订阅方案"
        string status "开通状态"
    }
```

### 核心规则

- **一个租户 = 一个客户企业**，可开通多个产品线
- **租户 ID 由系统生成**，不接受客户端指定
- **产品线间数据在租户内隔离** — GEO 数据和 CRM 数据互不可见
- **租户状态变更影响所有产品线** — 暂停/注销对全部产品生效

## 二、租户生命周期

```mermaid
stateDiagram-v2
    [*] --> PENDING: 平台创建/开通申请

    PENDING --> ACTIVE: 开通事务完成
    PENDING --> CANCELLED: 开通失败/主动取消

    ACTIVE --> SUSPENDED: 欠费/违规
    ACTIVE --> EXPIRED: 到期未续费
    ACTIVE --> CANCELLED: 主动销户

    SUSPENDED --> ACTIVE: 补缴/整改完成
    EXPIRED --> ACTIVE: 续费完成

    SUSPENDED --> CANCELLED: 长期欠费
    EXPIRED --> CANCELLED: 超期未续

    CANCELLED --> [*]: 30天后物理清除
```

### 状态转换规则

| 当前状态 | 可转换到 | 触发条件 | 影响 |
|---------|:---:|------|------|
| PENDING | ACTIVE | 原子开通事务完成 | 租户可正常使用 |
| PENDING | CANCELLED | 开通失败或主动取消 | 清理预分配资源 |
| ACTIVE | SUSPENDED | 欠费/违规 | 所有产品暂停访问 |
| ACTIVE | EXPIRED | 到期未续费 | 限制功能但不删数据 |
| ACTIVE | CANCELLED | 主动销户 | 30天后物理清除 |
| SUSPENDED | ACTIVE | 补缴/整改 | 恢复访问 |
| EXPIRED | ACTIVE | 续费 | 恢复完整功能 |
| CANCELLED | — | 终态 | 不可逆 |

### 重新激活安全要求

- Token 有效期不能超过租户到期时间
- 离开 ACTIVE 状态必须吊销该租户所有会话
- 平台控制面操作，不接受客户端指定 target tenant_id

## 三、原子开通事务

租户开通是一个不可分割的平台控制面操作：

```mermaid
flowchart TB
    START["接收开通请求"] --> VALIDATE["参数校验<br/>· 租户基本信息<br/>· 至少 1 个有效套餐<br/>· 初始管理员信息"]
    VALIDATE -->|"失败"| ERR["返回 400/409"]
    VALIDATE -->|"通过"| TX["开启数据库事务"]

    TX --> STEP1["① 创建 Tenant 记录<br/>tenant_id 由系统生成"]
    STEP1 --> STEP2["② 绑定业务套餐<br/>写入 TenantPermissionGroup"]
    STEP2 --> STEP3["③ 创建根部门<br/>dept_name = 企业名称"]
    STEP3 --> STEP4["④ 创建租户管理员角色<br/>菜单范围 = 套餐有效菜单"]
    STEP4 --> STEP5["⑤ 创建初始管理员用户<br/>password 加密存储"]
    STEP5 --> STEP6["⑥ 设置 lifecycle_status = ACTIVE"]
    STEP6 --> STEP7["⑦ 刷新授权缓存"]
    STEP7 --> COMMIT["提交事务"]

    COMMIT --> AUDIT["记录审计日志<br/>action=tenant.create"]
    AUDIT --> DONE["返回 tenant_id + 初始管理员信息"]

    style TX fill:#e8f5e9
    style COMMIT fill:#e3f2fd
```

**安全约束：**

- 整个流程在一个数据库事务内完成
- 管理员角色只能获取套餐有效菜单，永不获取平台控制面菜单
- 明文密码不出现于日志、审计、响应
- `tenant_id` 由事务内部生成，不接受客户端传入

## 四、多产品叠加

```mermaid
flowchart TB
    subgraph Tenant["客户 A (一个租户)"]
        direction TB
        GEO["GEO Engine<br/>Pro 套餐<br/>· 文章 30 篇/月<br/>· 品牌案例 10 个"]
        CRM["CRM<br/>Starter 套餐<br/>· 客户 500 个<br/>· 销售漏斗 3 个"]
    end

    subgraph Storage["存储隔离"]
        GEO_DB[("GEO 数据<br/>schema: geo")]
        CRM_DB[("CRM 数据<br/>schema: crm")]
        Shared[("共享数据<br/>租户基本信息、用户")]
    end

    Tenant --> GEO_DB
    Tenant --> CRM_DB
    Tenant --> Shared
```

- 产品线各自数据库 Schema 隔离
- 产品 A 无法直接查询产品 B 的数据
- 租户基础信息（名称、状态、用户）共享

## 五、租户上下文传递

```mermaid
flowchart LR
    GW["API 网关"] -->|"X-Tenant-Id: T_A<br/>X-User-Id: U_001<br/>X-User-Type: customer<br/>X-Mode: self"| Service
    Service -->|"tenant_id = T_A"| Biz
    Biz -->|"WHERE tenant_id = T_A"| Data
    Data -->|"Ent Privacy 层<br/>自动注入 tenant_id"| DB[("数据库")]
```

所有下游服务信任网关注入的 Header，无需自行解析 Token。租户隔离在每一层独立校验。
