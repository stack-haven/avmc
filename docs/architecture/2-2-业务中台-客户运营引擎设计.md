## 二、客户开通审核流程

```mermaid
flowchart TB
    SALES["业务员提交开通申请"] --> FORM["填写: 客户企业信息 + 选择产品线/档次 + 月付/年付"]
    FORM --> CALC["系统自动核算<br/>预估月费 + 业务员提成估算"]
    CALC --> SUBMIT["提交申请"]

    SUBMIT --> REVIEW{"代理审核"}
    REVIEW -->|"通过"| AUTO["系统自动开通<br/>① 创建租户<br/>② 开通产品线<br/>③ 创建 Owner 账号<br/>④ 建立代管关系"]
    REVIEW -->|"拒绝"| BACK["退回业务员 (附原因)"]

    AUTO --> NOTIFY["通知客户 (激活短信) + 通知业务员"]
    AUTO --> AUDIT["记录审计日志"]
```

## 三、代客管理会话

```mermaid
sequenceDiagram
    actor Sales as 业务员
    participant Console as 业务员控制台
    participant Auth as 认证中心
    participant Product as 产品服务
    participant Audit as 审计日志

    Sales->>Console: 选择客户 "XX餐厅" → 进入代管
    Console->>Auth: 请求代管 Token (target_tenant=T_A)

    Auth->>Auth: 校验代管授权关系
    Auth-->>Console: 代管 Token (mode=managed, tenant=T_A)

    Note over Console: UI 顶部显示: "代管模式: XX餐厅 [退出]"

    Sales->>Product: 录入品牌案例 (Header: X-Tenant-Id=T_A, X-Mode=managed)
    Product->>Product: 数据写入 T_A 的租户空间
    Product->>Audit: 记录: 张三(业务员) 代管 T_A 录入案例
    Product-->>Sales: 操作成功

    Sales->>Console: 退出代管
    Console->>Auth: 销毁代管 Token
    Console-->>Sales: 回到自身视角
```

### 代管安全约束

| # | 约束 |
|:---:|------|
| ① | 代管 Token 有效期 2 小时（短于普通 Token） |
| ② | 代管 Token 绑定目标租户，不可切换 |
| ③ | 所有操作标记 `mode=managed`，审计可区分 |
| ④ | 敏感操作在代管模式下拦截（修改密码/套餐/销户/导出） |
| ⑤ | 客户可随时查看代管操作记录 |
| ⑥ | 客户可一键终止所有代管 Token |

## 四、客户健康度分层

```mermaid
stateDiagram-v2
    [*] --> Healthy: 新客户开通

    Healthy --> Attention: 用量下降 / 注册 1-3 月
    Attention --> Healthy: 恢复活跃
    Attention --> Risk: 持续恶化

    Risk --> Attention: 干预有效
    Risk --> Churned: 干预无效

    Churned --> [*]

    state Healthy {
        [*] --> Active: 月活跃
        Active --> Normal: 用量 50-90%
        Normal --> Stable: 注册 > 3 月
    }

    state Attention {
        LowUsage: 用量 < 30%
        NewCustomer: 注册 1-3 月
        OverUsage: 连续超额
    }

    state Risk {
        NoOp30: 30 天无操作
        Hesitant: 续费前曾犹豫
        Complaints: 有投诉记录
    }

    state Churned {
        Expired: 到期未续
        Cancelled: 主动取消
    }
```

## 五、业务员离职交接

```mermaid
sequenceDiagram
    actor Agent as 代理
    participant Channel as 渠道引擎
    participant Customer as 客户运营
    participant Notify as 通知中心

    Agent->>Channel: 停用业务员 张三
    Channel->>Customer: 查询张三名下客户列表
    Customer-->>Agent: 返回客户列表 (5 个)

    Agent->>Customer: 批量分配给李四
    Customer->>Customer: 更新 CUSTOMER_ASSIGNMENT<br/>· 旧关系: status=transferred<br/>· 新关系: status=active
    Customer->>Customer: 记录历史关系

    Customer->>Notify: 通知 5 个客户
    Notify-->>Agent: "您的服务专员变更为李四 (139xxxx)"
```
