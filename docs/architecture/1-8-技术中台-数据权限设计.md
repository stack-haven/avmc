## 一、菜单权限 vs 数据权限

```mermaid
flowchart LR
    subgraph MenuAuth["菜单权限"]
        M1["用户能否看到 '客户列表' 页面?"]
        M2["用户能否点击 '新建客户' 按钮?"]
    end

    subgraph DataAuth["数据权限"]
        D1["用户在客户列表能看见哪些客户?"]
        D2["用户能编辑哪些客户的数据?"]
    end

    MenuAuth -->|"回答"| What["能做什么操作"]
    DataAuth -->|"回答"| Which["能操作哪些数据"]
```

**数据权限 = 在租户隔离基础上，控制租户内部不同角色能访问的数据范围。**

## 二、五级数据范围

```mermaid
graph TB
    subgraph Scopes["数据范围"]
        S1["① 全部数据<br/>租户内所有数据"]
        S2["② 仅本人<br/>只看自己创建/负责的数据"]
        S3["③ 本部门<br/>所属部门的数据"]
        S4["④ 本部门及下级<br/>部门 + 所有子部门"]
        S5["⑤ 自定义部门<br/>手动指定可见部门集合"]
    end

    S3 -->|"包含子部门"| S4
    S5 -.->|"多选"| S5
```

| 范围码 | 含义 | 典型角色 |
|:---:|------|------|
| 1 | 全部数据 | 租户管理员 |
| 2 | 仅本人 | 普通成员 |
| 3 | 本部门 | 部门主管 |
| 4 | 本部门及下级 | 部门总监 |
| 5 | 自定义部门 | 跨部门协作角色 |

## 三、权限计算流程

```mermaid
flowchart TB
    Request["查询请求"] --> TenantCheck{"租户隔离校验"}
    TenantCheck -->|"tenant_id 匹配"| UserRole["获取用户角色列表"]
    UserRole --> MultiRole{"多角色?"}

    MultiRole -->|"单角色"| SingleScope["取角色 data_scope"]
    MultiRole -->|"多角色"| UnionScope["合并所有角色范围<br/>取最宽"]

    UnionScope --> ShortCircuit{"全部数据或<br/>租户管理员?"}
    SingleScope --> ShortCircuit

    ShortCircuit -->|"是"| NoFilter["不加部门过滤"]
    ShortCircuit -->|"否"| BuildFilter["构建部门过滤条件<br/>· 本人: WHERE user_id = ?<br/>· 本部门: WHERE dept_id = user.dept_id<br/>· 及下级: WHERE dept.ancestors LIKE ?<br/>· 自定义: WHERE dept_id IN (?)"]

    NoFilter --> Result["返回结果"]
    BuildFilter --> Result
```

## 四、部门层级模型

```mermaid
graph TB
    Dept["根部门<br/>XX公司 (ancestors: [self])"]
    Dept1["技术部<br/>(ancestors: [root, self])"]
    Dept2["市场部<br/>(ancestors: [root, self])"]
    Dept1a["前端组<br/>(ancestors: [root, tech, self])"]
    Dept1b["后端组<br/>(ancestors: [root, tech, self])"]

    Dept --> Dept1
    Dept --> Dept2
    Dept1 --> Dept1a
    Dept1 --> Dept1b
```

- `ancestors` 字段存储完整祖先链
- 部门移动时事务内重写子树所有节点的 ancestors
- 移动前检测循环依赖（目标不能是自身的子孙）

## 五、资源分类

| 资源类型 | 权限模型 | 示例 |
|---------|---------|------|
| **自有资源** | 受数据范围控制 | 用户列表、部门、项目 |
| **共享配置** | 仅租户隔离 + 操作授权 | 字典、参数配置 |
| **审计资源** | 平台控制面 / 租户数据面 | 操作日志 |

共享配置资源不由部门数据范围约束，仅受 `tenant_id` 隔离保护。

## 六、接入新资源

新增业务资源接入数据权限时：

1. Repository 层调用 `DataScopeResolver` 构建过滤条件
2. 服务层声明资源分类（自有/共享/审计）
3. 测试覆盖跨租户和跨部门隔离

```text
// 典型调用模式
predicates := s.dataScopeResolver.Resolve(ctx, user)
users, err := s.userRepo.List(ctx, append(basePredicates, predicates...)...)
```
