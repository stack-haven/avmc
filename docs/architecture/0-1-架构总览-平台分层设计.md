## 二、产品层

### 职责

- 实现产品特有的业务逻辑和领域模型
- 定义产品自己的数据模型和 API
- 构建产品专属的前端界面和交互
- 通过 API 调用中台能力，不直接访问中台数据库

### 当前产品服务

| 产品 | 状态 | 定位 | 后端落点 |
|------|:---:|------|---------|
| GEO Engine | 📋 规划中 | 内容工程、知识库、AI 生成、后处理、发布、追踪 | `docs/services/geo-content-engine` |
| AI Agent Management | 📋 规划中 | 企业智能体、语音接入、工具调用、知识问答 | `docs/services/ai-agent-management` |
| App Version Management | 📦 历史参考 | 版本发布、灰度、下载、反馈、协议 | `docs/services/app-version-management` |

### 产品层约束

```mermaid
flowchart LR
    subgraph Right["✅ 允许"]
        R1["通过 API 调用中台能力"]
        R2["定义产品独有数据模型"]
        R3["注册产品菜单、定价、配额"]

```

### 产品服务与中台协作模式

产品服务不自行管理租户、用户、认证、会话等横向能力，全部通过 RPC + 中间件注入复用技术中台。

```mermaid
flowchart LR
    subgraph Product["产品服务（如 Evie / GEO）"]
        direction TB
        MW["认证中间件（注入）"]
        Biz["业务逻辑"]
        Data["产品自有数据"]
        MW --> Biz --> Data
    end

    subgraph Platform["技术中台"]
        Auth["认证授权"]
        Tenant["租户底座"]
        Quota["套餐配额"]
        Audit["操作审计"]
        Notify["通知中心"]
    end

    MW -.->|"JWT 验签（复用平台包）"| Auth
    Biz -.->|"gRPC 查询租户状态"| Tenant
    Biz -.->|"gRPC 检查/上报配额"| Quota
    Biz -.->|"写审计日志"| Audit
    Notify -.->|"订阅租户生命周期事件"| Product
```

**协作规则（强制）：**

| 规则 | 说明 |
|------|------|
| 认证复用 | 产品服务注入平台 JWT 中间件验签，不自建登录、不自己签发 token |
| 租户上下文 | `tenant_id` 从 JWT claims 提取，不接受客户端传入，不自己建 tenant 表 |
| 用户上下文 | `user_id` 从 JWT claims 提取，不自己建 user 表、不管理 session |
| 租户状态 | 需要实时租户状态时通过 gRPC 调租户底座，不在本地缓存 |
| 配额管控 | 通过配额 API 检查和上报，不自建计量逻辑 |
| 审计日志 | 写操作通过操作审计 API 记录，不自建审计表 |
| 生命周期事件 | 通过通知中心/Webhook 订阅租户暂停、注销等事件，做数据清理 |
| 模块边界 | `tenant_id` 只作为数据隔离键，不作为外键关联中台表 |

> 后续新增产品服务自动继承此协作模式，无需单独讨论。接入检查清单见 [4-1-产品服务模块接入规范](./4-1-治理-产品服务模块接入规范.md)。

## 三、业务中台

### 职责

- 跨产品的商业化运营能力，所有产品共用的"管生意"能力
- 管理产品线注册、客户关系、订阅计费、渠道代理和佣金结算
- 不包含任何具体产品的业务逻辑

### 模块总览

```mermaid

        CO["客户运营引擎<br/>开通审核·代客管理·客户健康度·客户移交"]
```

### 平台控制面 vs 租户数据面

```mermaid
graph TB
    subgraph Control["平台控制面 Platform Control Plane"]
        direction TB
        C1["租户生命周期管理"]
        C2["业务套餐配置"]
        C3["平台级参数定义"]
        C4["存储渠道管理"]
        C5["通知模板管理"]
        C6["全局审计查询"]
    end

    subgraph Data["租户数据面 Tenant Data Plane"]
        direction TB
        D1["租户内用户/角色/部门管理"]
        D2["当前租户参数覆盖"]
        D3["文件上传/下载/管理"]
        D4["我的通知/已读/未读"]
        D5["当前租户操作日志"]
    end

    Control -.->|"平台管理员<br/>(platform_operator=true)"| Control
    Data -.->|"租户管理员<br/>(tenant_admin)"| Data
```

**关键安全规则：**

- 平台控制面操作需要 `is_platform=true` + JWT `platform_operator=true` + Casbin 平台策略 + 中间件四重校验
- 租户数据面 API 从 auth context 提取 `tenant_id`，不接受客户端传入
- `super_admin` 是租户级角色，不是平台级角色

## 五、层间协作模式

### 典型流程：客户开通

```mermaid
sequenceDiagram
    actor Sales as 业务员
    participant BizPlatform as 业务中台·客户运营
    participant TenantBase as 技术中台·租户底座
    participant Billing as 技术中台·配额引擎
    participant Notify as 技术中台·通知中心
    participant Audit as 技术中台·操作审计

    Sales->>BizPlatform: 提交客户开通申请
    BizPlatform->>BizPlatform: 代理审核通过
    BizPlatform->>TenantBase: 创建租户 + 开通产品线
    TenantBase-->>BizPlatform: 租户创建成功
    BizPlatform->>Billing: 创建订阅 + 设置配额
    Billing-->>BizPlatform: 订阅生效
    BizPlatform->>Notify: 发送激活通知
    Notify-->>BizPlatform: 通知已入队
    BizPlatform->>Audit: 记录开通审计
    Audit-->>BizPlatform: 已记录
    BizPlatform-->>Sales: 开通完成
```

### 产品调用中台

```mermaid
sequenceDiagram
    actor User as 用户
    participant Product as 产品服务 (GEO)
    participant GW as API 网关
    participant Billing as 配额引擎
    participant Storage as 文件中心

    User->>GW: POST /geo/articles (生成文章)
    GW->>GW: JWT 校验 + 注入 X-Tenant-Id
    GW->>Product: 转发请求
    Product->>Billing: 检查文章配额 (GET /billing/usage/check)
    Billing-->>Product: { remaining: 5, allowed: true }
    Product->>Product: 执行文章生成逻辑
    Product->>Billing: 上报用量 (POST /billing/usage/report)
    Product->>Storage: 保存生成结果附件
    Product-->>User: 文章生成成功
```

## 六、微服务拆分条件

当前阶段采用 **大仓 + 模块化服务边界优先** 策略。不因新增模块默认创建新的 Kratos service。

只有满足以下条件之一，才进入服务拆分评审：

| 条件 | 示例 |
|------|------|
| 需要独立部署 | 独立的发版节奏、独立的灰度策略 |
| 需要独立扩缩容 | 某模块 QPS 远高于其他模块 |
| 独立公共 API 或外部接入 | 对外提供 SDK 或第三方可调用的独立 API |
| 独立数据生命周期或合规边界 | 数据需要独立存储、独立备份、独立合规审计 |
| 清晰业务域和团队 ownership | 有独立团队全权负责该模块 |

```mermaid
flowchart TB
    NewModule["新模块需求"] --> Q1{"需要独立部署?"}
    Q1 -->|"否"| Q2{"需要独立扩缩容?"}
    Q2 -->|"否"| Q3{"独立公共 API?"}
    Q3 -->|"否"| Q4{"独立数据生命周期?"}
    Q4 -->|"否"| Q5{"独立团队 ownership?"}
    Q5 -->|"否"| Monorepo["在 platform/admin 大仓内实现"]

    Q1 -->|"是"| Review["服务拆分评审"]
    Q2 -->|"是"| Review
    Q3 -->|"是"| Review
    Q4 -->|"是"| Review
    Q5 -->|"是"| Review

    Review --> Decision{"评审结论"}
    Decision -->|"通过"| NewService["新建 Kratos service"]
    Decision -->|"不通过"| Monorepo
```
