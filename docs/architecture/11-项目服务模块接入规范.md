# 项目服务模块接入规范

日期：2026-07-10  
状态：生效  
范围：项目开发底座后端、前端和项目服务模块

## 1. 目标

本规范用于保证新增模块不会破坏项目开发底座边界。所有底座基础模块和业务项目服务模块都必须先完成接入清单，再进入实现。

默认原则：

- 底座基础能力落在 `backend-service/app/platform/admin` 和 `frontend-service/apps/web-antd-admin`。
- 具体业务服务不得进入 `platform/admin`，除非它只是“项目服务配置入口”而非业务生命周期本体。
- 新模块必须先定义契约、权限、租户边界、数据模型、测试和 Mock 数据。

## 2. 后端接入清单

新增后端模块必须按以下顺序交付：

1. 在 `backend-service/proto` 定义 Protobuf 契约。
2. 生成 `backend-service/api`、HTTP/gRPC 和 OpenAPI 输出。
3. 在 `internal/service` 完成请求校验、field mask 合并、上下文提取和响应组装。
4. 在 `internal/biz` 放业务规则、状态机、权限校验、租户边界和 repository interface。
5. 在 `internal/data` 实现 repository、事务、缓存、Ent 转换和租户查询范围。
6. 在 `internal/data/ent/schema` 定义 schema，复用租户、平台和审计 mixin。
7. 更新 Wire provider、HTTP/gRPC 注册、配置和迁移入口。
8. 补 seed/mock 数据，保证初始化可重复执行。
9. 补测试和文档，记录验证命令。

禁止手工修改生成目录：`backend-service/api`、`internal/conf`、`internal/data/ent/gen`。

## 3. 权限与租户边界

每个模块必须显式说明：

- 是否属于平台控制面。
- 普通租户是否可访问。
- 是否读取当前租户上下文。
- 是否允许平台管理员跨租户操作。
- 后端接口权限码对应的菜单或按钮来源。
- 数据层是否强制 tenant scope。

普通租户数据接口必须满足：

- service 层从认证上下文提取当前租户，不能相信前端传入的租户 ID。
- data 层查询必须带租户范围或经过平台身份守门。
- 前端隐藏菜单和按钮不是安全边界。

## 4. 前端接入清单

新增前端模块必须包含：

- API 文件和 request/response 类型。
- 路由、菜单、按钮权限码。
- 列表、创建、编辑、状态切换和删除的基础交互。
- 字典、参数、状态枚举的统一渲染方式。
- 权限不足、接口失败和空状态处理。
- 与后端 Mock 数据一致的演示数据。

当前阶段前端 API 类型允许按项目现有手写方式维护；不恢复使用旧的 `src/api/gen` 作为默认来源。

## 5. 测试接入清单

新增模块至少补齐：

- biz 层业务规则和错误分支测试。
- service 层参数转换、field mask、上下文和响应结构测试。
- data 层租户隔离、事务、缓存和唯一性测试。
- 权限测试：平台身份、租户管理员、普通租户角色。
- Mock 初始化测试或可重复运行验证。

跨租户访问、权限撤销和缓存失效属于强制测试项，不能只用前端流程验证。

## 6. 文档与验收

新增模块必须更新：

- 架构或 ADR 文档：说明模块边界和关键决策。
- 产品模块文档：说明用户目标、字段和验收标准。
- 开发记录：说明测试命令、迁移影响和未完成风险。

验收标准：

- 后端全量测试通过。
- 前端类型检查和构建通过。
- Mock 数据可重复初始化。
- 普通租户和平台管理员的权限差异可验证。
- 没有把具体业务生命周期写入 `platform/admin`。
