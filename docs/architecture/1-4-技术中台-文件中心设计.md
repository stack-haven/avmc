## 二、多存储 Provider 模型

```mermaid
graph TB
    subgraph Providers["存储渠道"]
        P1["S3 Provider<br/>· Bucket: ark-files<br/>· Region: auto<br/>· 默认渠道 ✅"]
        P2["Local Provider<br/>· Path: /data/files<br/>· 测试/开发用"]
    end

    subgraph File["文件对象"]
        F1["file_001<br/>provider: S3<br/>bucket: ark-files<br/>object_key: T_A/images/logo.png"]
    end

    P1 -->|"创建时捕获"| F1
```

- 支持多个存储 Provider 共存
- 任一时刻只有一个默认 Provider
- 文件对象记录创建时的 Provider 快照
- 切换默认 Provider 不影响历史文件

## 三、文件上传流程

```mermaid
sequenceDiagram
    actor User as 用户
    participant API as 文件中心 API
    participant Quota as 配额引擎
    participant Storage as 对象存储
    participant DB as 数据库

    User->>API: ① 创建上传会话 (POST /files/upload-session)
    API->>Quota: 检查 files + storage.bytes 额度
    alt 额度不足
        Quota-->>API: 403 QUOTA_EXCEEDED
        API-->>User: 额度不足
    else 额度充足
        API->>API: 生成 presigned URL
        API-->>User: { session_id, upload_url, expires_at }
    end

    User->>Storage: ② 客户端直传文件 (PUT presigned URL)
    Storage-->>User: 上传成功

    User->>API: ③ 确认上传 (POST /files/confirm)
    API->>Quota: Occupy(idempotency_key)
    API->>DB: 创建 file_object 记录
    API-->>User: { file_id, public_url }
```

## 四、存储目录隔离

```text
/{tenant_id}/{product_code}/{resource_type}/{filename}
```

| 租户 | 产品 | 示例路径 |
|------|------|---------|
| T_A | GEO | `T_A/geo/images/article_hero.png` |
| T_A | CRM | `T_A/crm/attachments/contract.pdf` |
| T_B | GEO | `T_B/geo/images/logo.png` |

不同租户和产品的文件物理隔离，无法通过猜测 URL 跨租户访问。
