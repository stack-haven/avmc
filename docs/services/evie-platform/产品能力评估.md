### 2.2 市场定位

```
                低                             高
            传统 ASR API                    企业智能体
            (百度/讯飞)                      (AI Agent)

 技术壁垒 ────────────────────────────────────→

            语音助手                         Evie
            (通用)                    ← 你的位置

                ↑                            ↑
            通用场景                     垂直企业
```

Evie 定位在"企业垂直场景 + 中等技术壁垒"，不是一个通用语音 API，而是**紧耦合企业数据**的认知层产品。这个卡位合理——通用 ASR 赛道已经红海，但企业语义增强是蓝海。

## 四、技术架构评估

### 4.1 优势

| 方面 | 评价 |
|------|------|
| **技术选型** | FunASR（中文优化）→ Whisper Ensemble → 微调，路线务实 |
| **纠错架构** | 规则→算法→LLM 三级策略，成本可控（95% 场景不走 LLM） |
| **字典设计** | 四级字典 + 别名自动生成 + ES/Milvus 双引擎，企业场景纵深足够 |
| **平台复用** | 不重新发明租户/认证/审计，架构清爽 |
| **数据隔离** | DB/Redis/ES/Milvus 全链路，无遗漏 |
| **Ent Mixin 模式** | 复用 pkg 公共层，BaseMixin 组合 + SoftDeleteMixin + FilterTenantRule |

### 4.2 技术风险

| 风险 | 等级 | 说明 | 缓解 |
|------|:---:|------|------|
| FunASR 部署运维 | 🟡 中 | 私有化部署需要 GPU 资源、模型管理、版本升级 | docker-compose 先行验证；备选 Whisper API |
| 拼音纠错准确率 | 🟡 中 | 同音词歧义（功课/攻克）依赖上下文判断 | Phase 2 加大测试集；Phase 3 LLM 兜底 |
| LLM 延迟不可控 | 🟢 低 | 仅低置信度场景调用（<5%），其他走规则 | 超时 3s + 降级为保持原文 |
| ES/Milvus 运维 | 🟡 中 | 引入两组新中间件 | Phase 1-2 不引入，MySQL + 内存扛；Phase 3 按需上 |
| 冷启动无字典 | 🟡 中 | 新租户无字典数据，纠错不生效 | 组织同步自动导入 + 系统字典预置 |
| GPU 资源依赖 | 🟡 中 | ASR 模型推理需要 GPU | 初期可 CPU（FunASR 有 onnx 导出）；中后期上 GPU |

## 六、平台依赖与缺口

### 6.1 已就绪的平台能力

| 平台能力 | 状态 | Evie 如何使用 |
|---------|:---:|------|
| 租户底座 | ✅ 已实现 | gRPC 查询租户状态；tenant_id 从 JWT 提取 |
| 认证授权 | ✅ 已实现 | 注入 JWT 中间件验签 |
| 套餐配额 | ✅ 已实现 | API 检查 ASR 时长/纠错次数/字典容量 |
| 操作审计 | ✅ 已实现 | 写审计日志 |
| 文件中心 | ✅ 已验证 | 音频上传/存储 |
| 通知中心 | ✅ 已验证 | 纠错确认推送 |
| 参数配置 | ✅ 已验证 | 纠错阈值、热词权重等动态配置 |

### 6.2 缺失的平台能力（阻塞项）

| 缺口 | 优先级 | 影响 | 说明 |
|------|:---:|------|------|
| **租户生命周期事件发布** | 🔴 P1 | Phase 3 阻塞 | 租户暂停/注销时，Evie 无法收到通知做数据清理。当前 Webhook 中心已实现订阅/签名/投递，但租户暂停/恢复/注销事件未纳入标准事件类型 |
| **产品注册中心** | 🟡 P3 | 生产上线阻塞 | Evie 作为产品服务需要注册产品信息、菜单、定价、配额方案。当前可手工配置，正式上线前需要系统化 |

### 6.3 建议：先发布基础事件，不等到产品注册中心

```
当前最紧急缺口：租户生命周期事件（P1）

建议的 4 个标准事件类型（加入 Webhook 事件中心）：
  evie.tenant.suspended   → Evie 拒绝该租户新请求
  evie.tenant.resumed     → Evie 恢复该租户访问
  evie.tenant.cancelled   → Evie 标记数据待清理
  evie.tenant.expired     → Evie 限制配额API查询

实现路径：
  1. 平台 Webhook 中心注册这 4 个事件类型（1d）
  2. Evie 订阅 + 处理回调（1d）
  3. 不需要产品注册中心 — 可以先手工配置
```

## 九、竞争分析简要

| 竞品/方案 | 语音识别 | 企业字典 | 纠错增强 | 多租户 SaaS | 部署方式 |
|----------|:---:|:---:|:---:|:---:|------|
| 百度语音 API | ✅ | ❌ | ❌ | ❌ | 公有云 |
| 讯飞语音 | ✅ | 热词有限 | ❌ | ❌ | 公有云/私有 |
| 阿里语音 AI | ✅ | 自学习平台 | 有限 | ❌ | 公有云 |
| **Evie** | ✅ FunASR | ✅ 四级字典 | ✅ 五路纠错 | ✅ | 私有化 |

Evie 的核心优势不在 ASR 识别本身（那是模型的事），而在**企业语义增强层的纵深**。如果只做 ASR 接入，就是个 FunASR proxy，不值一个产品。字典 + 纠错 + 反馈闭环才是竞争力。
