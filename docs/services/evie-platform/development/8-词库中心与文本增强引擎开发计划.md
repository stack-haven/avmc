## 二、任务拆分（每个任务独立可验收）

### M0：菜单重构 + 热词清理

- **目标**：菜单结构对齐新设计；热词全链路删除。
- **交付**：
  - `seed_evie.go` 菜单/按钮更新（词库中心 7 页 + 文本增强 3 页，删除热词菜单）
  - 删除热词：`hotword.proto`、`biz/hotword.go`、`data/hotword_repo.go`、`service/hotword_service.go`、`ent/schema/hotword.go`、前端热词页、热词 locale
  - 文档同步（删除热词相关描述）
- **验收**：mock 运行后菜单树正确；热词代码/文档 grep 无残留；`go build` 通过。

### M1：领域模型 + Ent Schema

- **目标**：建立词库中心数据模型。
- **交付**（Ent Schema + Atlas 迁移）：
  - `dictionary`：scope(PLATFORM/SYSTEM/TENANT)、source、status、name
  - `dictionary_entry`：dictionary_id、standard_text、category、description、status、source、source_id、priority、pinyin、pinyin_initial、normalized_text
  - `dictionary_relation`：entry_id、relation_type(ALIAS/CORRECTION/HOMOPHONE/PHONETIC_SIMILAR/ABBREVIATION/RELATED)、related_text、target_entry_id、status
  - `dictionary_category`：code、name、builtin、status
  - `dictionary_version`：dictionary_id、version_no、status、snapshot
  - `dictionary_conflict`：input、candidate、source_scope、source_dictionary、priority、resolved_candidate
  - 变更记录（复用 audit 或独立 change_log）
  - 多租户隔离（TenantID mixin）
- **验收**：`make migrate` 成功；schema 覆盖文档第六章~第十一章模型。

### M2：词库 + 词条 CRUD

- **目标**：词库中心基础 CRUD。
- **交付**：`dictionary.proto`（重写）+ 六层实现（Dictionary、DictionaryEntry CRUD + 多租户隔离）。
- **验收**：创建词库（scope=TENANT）→ 创建词条（田华/PERSON）→ 查询/更新/禁用。

### M3：词条关系 CRUD

- **目标**：关系模型（六类关系）。
- **交付**：`dictionary_relation` 六层 CRUD；ALIAS/CORRECTION 等类型。
- **验收**：创建关系「小田 → ALIAS → 田华」「金种子 → CORRECTION → 金种籽」→ 查询。

### M4：分类 + 版本

- **目标**：内置分类 + 词库版本。
- **交付**：分类 CRUD（内置只读）+ 版本发布（生成 version_no + snapshot）。
- **验收**：内置分类可见；发布版本 v1 → v2，版本列表正确。

### M5：Vocabulary Context 构建 + 缓存

- **目标**：运行时词库上下文。
- **交付**：词库索引构建（Trie/HashMap）+ Context 组装（TENANT > SYSTEM > PLATFORM）+ 缓存 key + 冲突检测。
- **验收**：同输入多租户隔离（Case 8）；冲突记录可查询。

### M6：文本增强核心（确定性流水线）

- **目标**：文本增强引擎确定性部分。
- **交付**：8 层流水线骨架；①清洗 ②口水词 ③词库匹配 ④别名解析 ⑤确定性替换 + **锁定机制**。
- **验收**：Case 1（别名）/ Case 2（确定性）/ Case 3（口水词）/ Case 7（锁定）。

### M7：文本增强推断（拼音 + 模糊 + 上下文）

- **目标**：推断性处理。
- **交付**：⑥拼音纠错 ⑦模糊匹配 ⑧上下文纠错；score/threshold/REPLACE/SUGGEST/KEEP；防过度纠正。
- **验收**：Case 4（拼音）/ Case 5（短语标准化）/ Case 6（低置信度 SUGGEST）。

### M8：Policy + Enhancement Mode

- **目标**：策略配置与三档模式。
- **交付**：Policy（8 开关，阈值内置不开放）+ HIGH_PERFORMANCE/STANDARD/HIGH_ACCURACY + Profile 绑定。
- **验收**：切换模式，流水线各层按开关执行/跳过。

### M9：可观测 + 增强记录 ✅（已完成）

- **目标**：分阶段耗时与请求记录。
- **交付**：增强记录（request_id/tenant_id/policy_id/context_version/raw/enhanced/分阶段耗时）；降级（单阶段失败不阻断）。

## 四、演进预留（第二期不破坏的关键设计）

> 这些决策若不在第一期定好，第二期演进（热词生成/LLM/反馈闭环/NER 多消费者）将导致破坏性重构。

### 4.1 Vocabulary Context 必须是「通用语言上下文」（M5 关键）

文档第十七节要求 Context 同时服务：`ASR Hotword Builder`、`Text Enhancement`、`Future NLP/Entity Recognition`。
因此 M5 的 Context 接口设计为**通用语言上下文**（提供词条/关系/分类的查询能力），而非「文本增强专用」。文本增强只是其中一个消费者。

### 4.2 correction_rule 表删除，统一融入 DictionaryRelation（M1 关键）

现有 `correction_rule`（source→target）与文档的 `DictionaryRelation(CORRECTION)` 语义重叠。
第一期必须**删除 correction_rule 表**，确定性替换统一走关系模型，避免「两套纠错知识」的历史包袱。

### 4.3 Entry 支持 WORD / PHRASE（M1 关键）

文档第四十节要求短语级标准化（如「200个种籽→200颗种籽」）。
`DictionaryEntry` 需有 `entry_type`（WORD/PHRASE）或等价字段，词库 Trie 优先整体匹配短语。

### 4.4 版本 snapshot 是「快照」而非「引用」（M4 关键）

文档第十五节要求版本失效 + 异步重建，即版本代表某个时点的词库状态。
`DictionaryVersion.snapshot` 必须是词条/关系的**时点快照**（复制语义），否则旧版本会随词条修改而变化，失去版本意义。

### 4.5 流水线输入含 ASR Confidence，且支持流式增量（M6 关键）

文档第二十九节要求接收 segment/word 级 ASR confidence 作为算法特征；第四十五节要求流式增量处理。
因此 Text Enhancement Engine 的输入需预留 ASR confidence 字段，并提供「整段」与「流式增量（轻量+Final 完整）」两种入口，避免第二期重写流水线。

### 4.6 Policy 阈值预留开放（M8 关键）

文档第三十二节：阈值第一期内置，未来「高级策略」再开放。
M8 的 Policy 结构预留阈值从「系统内置常量」演进为「可配置字段」的路径（先硬编码 + 注释标记）。

### 4.7 反馈与可观测数据基础（M9 预留）

文档第五十节要求保留 Enhancement Feedback 数据基础（未来规则/词库/模型优化）。
M9 的增强记录表预留反馈字段（用户判断正确/错误），第一期不实现 ML，但数据结构就位。

## 五、实施顺序与原则

- 按 M0 → M11 顺序，每个任务独立验收后再进入下一个。
- 数据模型优先（M0-M1），确定性流水线优先于推断性（M6 先于 M7）。
- 中途临时测试发现的调整，即时同步本文档。
- 数据库 schema 变更走 Atlas 迁移，菜单/mock 数据同步更新 `seed_evie.go`。
