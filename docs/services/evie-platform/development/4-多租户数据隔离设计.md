## 一、设计原则

Evie 作为产品服务，**不重复造轮子**，所有租户管理能力复用以 Ark Tech Platform 技术中台的**租户底座**。

| 维度 | 复用策略 |
|------|---------|
| 租户标识 | 使用平台统一 `tenant_id`，从 JWT auth context 提取 |
| 租户生命周期 | 不自己管理，由平台租户底座负责 |
| 认证 | 复用平台 JWT，Service 层注入提取 |
| 权限 | 平台权限码 + Evie 自身资源权限 |
| 配额 | 调用平台套餐配额 API |

---

## 二、数据隔离层次

```
应用层     Service 层从 auth context 提取 tenant_id，不信任客户端传入
  │
数据库层   Ent query 强制 where tenant_id
  │
缓存层     Redis Key 前缀: evie:{module}:{tenantID}:...
  │
文件层     平台文件中心 key pattern 携带 tenant_id
```

> 语义检索能力由文本增强引擎（8 层流水线中的「模糊匹配」+「上下文纠错」步骤）覆盖，不引入独立的 ES / Milvus。

## 三、Service 层 — tenant_id 提取（强制）

```go
// app/evie/service/internal/service/dictionary_service.go（实际代码）

// 所有 Evie 接口统一从 auth context 提取 tenant_id。
// 底跨服务鉴权委托由 pkg/auth/authz/grpc/ 提供：IsAuthorized 通过后才有权进入 Service 层。
func (s *DictionaryService) ListDictionaries(ctx context.Context, req *pb.ListDictionariesRequest) (*pb.ListDictionariesResponse, error) {
    tenantID, err := authz.TenantIDFromContext(ctx)
    if err != nil {
        return nil, err
    }
    // 永远不相信客户端传入的 tenant_id，使用从 JWT 提取的 tenantID
    return s.uc.ListDictionaries(ctx, tenantID, req)
}
```

## 四、数据库层 — Ent 查询强制过滤

### 4.1 Data 层封装

```go
// app/evie/service/internal/data/dictionary_repo.go（实际代码）

type DictionaryRepo struct {
    client *ent.Client
}

// 所有 repo 方法强制传入 tenantID。
// vocab scope = PLATFORM 时传 tenantID=0，查询全局共享词库。
func (r *DictionaryRepo) ListDictionaries(ctx context.Context, tenantID int64, scope string, filter DictionaryFilter) ([]*ent.Dictionary, error) {
    query := r.client.Dictionary.Query().
        Where(dictionary.TenantIDEQ(tenantID)) // 强制过滤

    if scope != "" {
        query = query.Where(dictionary.ScopeEQ(dictionaryScope(scope)))
    }
    if filter.Status != nil {
        query = query.Where(dictionary.StatusEQ(*filter.Status))
    }

    return query.All(ctx)
}

// VocabularyContext 构建：合并 PLATFORM → SYSTEM → TENANT 三级，
// 同名词条由 TENANT 覆盖 SYSTEM 覆盖 PLATFORM（优先级递增）。
// 见 app/evie/service/internal/biz/vocabulary.go。
```

### 4.2 Ent Schema 要求

所有租户数据表必须包含 `tenant_id` 字段，并建立索引：

```go
func (Dictionary) Fields() []ent.Field {
    return []ent.Field{
        field.Int64("tenant_id"),                       // 必须字段
        field.String("scope"),                          // PLATFORM / SYSTEM / TENANT
        // ...
    }
}

func (Dictionary) Indexes() []ent.Index {
    return []ent.Index{
        index.Fields("tenant_id", "name").Unique(),     // 租户级别唯一索引
        index.Fields("tenant_id", "scope", "status"),   // VocabularyContext 查询索引
    }
}
```

## 五、缓存层 — VocabularyContext 缓存

VocabularyContext（词库上下文合并结果）由业务进程内的 sync.Map + 可选 Redis 二级缓存持有。

```go
// app/evie/service/internal/biz/vocabulary.go（实际代码）

// VocabularyBuilder 构建并缓存 VocabularyContext（PLATFORM→SYSTEM→TENANT 合并）。
// 缓存键: tenantID → context_version → VocabularyContext。
// 失效触发: 词库/词条/关系任意写入都会 bump context_version。
type VocabularyBuilder struct {
    repo       DictionaryRepo
    cache      sync.Map // tenantID → *vocabCacheEntry
}

type vocabCacheEntry struct {
    version int64
    ctx     *VocabularyContext
}

func (b *VocabularyBuilder) Build(ctx context.Context, tenantID int64) (*VocabularyContext, error) {
    currentVersion := b.repo.CurrentContextVersion(ctx, tenantID)
    if entry, ok := b.cache.Load(tenantID); ok {
        if entry.(*vocabCacheEntry).version == currentVersion {
            return entry.(*vocabCacheEntry).ctx, nil
        }
    }
    vc, err := b.buildFromRepo(ctx, tenantID, currentVersion)
    if err != nil {
        return nil, err
    }
    b.cache.Store(tenantID, &vocabCacheEntry{version: currentVersion, ctx: vc})
    return vc, nil
}
```

### 缓存策略

| 数据类型 | TTL/失效策略 | 位置 |
|---------|-------------|------|
| VocabularyContext | 写入触发 version bump，sync.Map 命中即返回 | 进程内 sync.Map |
| 增强策略 Policy/Profile | 写时失效（cache-aside） | 可选 Redis |
| ASR 识别记录 | 持久化即可，不预热 | MySQL |

## 六、文件隔离

语音文件存储复用以平台**文件中心**。

```go
// audio/recordings 存储路径
// {bucket}/{tenant_id}/{date}/{session_id}.{ext}
const audioPathPattern = "evie-audio/%d/%s/%s.wav"

func (s *ASRService) SaveAudio(ctx context.Context, tenantID int64, sessionID string, data []byte) (string, error) {
    key := fmt.Sprintf(audioPathPattern, tenantID, time.Now().Format("2006-01-02"), sessionID)
    // 调用平台文件中心上传
    url, err := s.fileClient.Upload(ctx, key, data, "audio/wav")
    return url, err
}
```

## 七、跨服务鉴权与审计委托

Evie 所有接口的鉴权与审计通过 gRPC 委托平台，避免在 Evie 内重复维护 Casbin 策略：

| 能力 | gRPC 调用 | 平台实现 |
|------|----------|---------|
| 鉴权 | `platform.service.v1.AuthService.IsAuthorized` | `pkg/auth/authz/grpc/` |
| 审计 | `platform.service.v1.OperationLogService.CreateOperationLog` | `pkg/audit/grpc/` |

平台 RPC 上携带原始 Bearer 头（通过 `authn.ForwardAuthToken`），
统一由平台做 JWT 校验 + Casbin 策略匹配。
跨服务调用免重复签发 token。

详见 [8-词库中心与文本增强引擎开发计划](./8-词库中心与文本增强引擎开发计划.md)。

## 八、安全设计清单

| 检查项 | 要求 | 实现方式 |
|-------|------|---------|
| tenant_id 来源 | 仅从 JWT 提取 | `authz.TenantIDFromContext(ctx)` |
| 客户端传入 tenant_id | 忽略或校验与 JWT 一致 | Service 层覆盖 |
| 数据查询 | 强制 where tenant_id | Data 层封装，无遗漏 |
| VocabularyContext 缓存 key | sync.Map 显式以 tenantID 为键 | `VocabularyBuilder.Build` |
| 文件存储 | 租户目录隔离 | 文件中心 key pattern |
| 鉴权 | 跨服务 gRPC 委托平台 IsAuthorized | `pkg/auth/authz/grpc/` |
| 审计 | 跨服务 gRPC 委托平台 OperationLog | `pkg/audit/grpc/` |
| 租户删除 | 级联清理所有数据 | 平台异步任务统一调度 |
