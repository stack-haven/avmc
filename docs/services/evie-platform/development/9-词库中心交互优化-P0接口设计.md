## 二、proto 草案

### 2.1 GetDictionaryStats（新增）

**文件**：`backend-service/proto/evie/service/v1/dictionary.proto`（追加到 DictionaryService）

```protobuf
// DictionaryStats 词库统计指标（词库详情页顶部 + 工作台健康度聚合）。
message DictionaryStats {
  uint32 dictionary_id = 1;

  // 基础计数
  int32 entry_count = 2;                    // 词条总数（含已禁用）
  int32 enabled_entry_count = 3;            // 启用词条数
  int32 relation_count = 4;                 // 关系总数
  int32 version_count = 5;                  // 已发布版本数
  int32 unresolved_conflict_count = 6;      // 未解决冲突数（status=PENDING）

  // 健康度（基于近 7 天 EnhancementLog 计算）
  double hit_rate = 7;                      // 词库命中率（命中词条/总请求）
  double avg_recognition_confidence = 8;    // 平均识别置信度（来自关联的 AsrRecord）

  // 时间戳
  string last_modified_at = 20;             // 最近一次词条/关系变更时间
}

message GetDictionaryStatsRequest {
  uint32 dictionary_id = 1 [(buf.validate.field).uint32 = {gt: 0}];
}

message GetDictionaryStatsResponse {
  DictionaryStats stats = 1;
}

// DictionaryService 新增方法
service DictionaryService {
  // ... existing rpcs ...

  // GetDictionaryStats 查询词库统计指标。
  // 可见性按词库 scope 自动应用：
  //   - scope=PLATFORM/SYSTEM：ctx 租户可见
  //   - scope=TENANT：仅 owner 租户可见
  rpc GetDictionaryStats(GetDictionaryStatsRequest) returns (GetDictionaryStatsResponse) {
    option (google.api.http) = {
      get: "/evie/v1/dictionaries/{dictionary_id}:stats"
    };
  }
}
```

**biz 实现要点**：
- 4 个 COUNT(*) 用 ent.GroupBy 单查询聚合（避免 N+1）
- `hit_rate` 计算：近 7 天 `EnhancementLog.changes_json` 中 `vocab_match_time_ms > 0` 的记录比例
- `avg_recognition_confidence`：通过 `AsrRecord → EnhancementLog` JOIN（当前 schema 未建关联，按 `session_id` 间接 JOIN）
- 多租户隐私：`biz` 层调用 `DictionaryRepo.GetByID(ctx, id)` 触发 scope 可见性校验

**Operation 常量**：`eviev1.OperationDictionaryServiceGetDictionaryStats`

### 2.2 ListRelationsByDictionary（新增）

**文件**：同上

```protobuf
// ListRelationsByDictionaryRequest 词库级别关系列表请求。
// 与 ListRelations 的区别：无需先选 entryId，一次性返回词库下所有词条的关系。
message ListRelationsByDictionaryRequest {
  uint32 dictionary_id = 1 [(buf.validate.field).uint32 = {gt: 0}];
  int32 page_size = 2;
  string page_token = 3;
  string relation_type = 4; // 可选筛选
  string keyword = 5;       // 可选筛选（匹配 entry.standard_text 或 relation.related_text）
}

message ListRelationsByDictionaryResponse {
  repeated DictionaryRelation relations = 1; // 字段已补全，见 2.3
  int32 total = 2;
  string next_page_token = 3;
}

// DictionaryService 追加：
rpc ListRelationsByDictionary(ListRelationsByDictionaryRequest) returns (ListRelationsByDictionaryResponse) {
  option (google.api.http) = {
    get: "/evie/v1/dictionaries/{dictionary_id}/relations"
  };
}
```

**biz 实现要点**：
- SQL：`SELECT r.* FROM dictionary_relations r INNER JOIN dictionary_entries e ON r.entry_id = e.id WHERE e.dictionary_id = ?`
- 复用 `DictionaryRepo.ListRelationsByDictionary` 新增方法
- 多租户隐私：词库 scope 可见性 + 词条所属词库可见性（双重校验）
- 性能：建议加联合索引 `(dictionary_id, entry_id, relation_type)`

**Operation 常量**：`eviev1.OperationDictionaryServiceListRelationsByDictionary`

### 2.3 DictionaryRelation 字段补全（修改现有 message）

**文件**：同上

```protobuf
message DictionaryRelation {
  // ... existing fields ...

  // —— 优化新增字段（自然语言化展示用，前端 JOIN 已经在 biz 层完成）——
  string entry_standard_text = 11;      // 所属词条的标准词/短语
  string entry_category = 12;           // 所属词条的分类
  string dictionary_name = 13;          // 所属词库名（跨词库聚合时显示）
  string related_standard_text = 14;    // 关联目标的标准词（同义词关系时填 target_entry 的 standard_text）
  uint32 related_tenant_id = 15;       // 关联目标所在租户（跨租户场景，用于权限判断）
}
```

**buf breaking 检查**：新增字段不影响 wire 兼容性（proto3 默认 optional 行为，老客户端忽略未知字段）。

**biz 实现要点**：
- `ListRelations` 和 `ListRelationsByDictionary` 都需在返回前 JOIN dictionary_entries 与 dictionary 表
- 推荐在 biz 层做单次批量查询后内存拼接，避免 N+1

### 2.4 GeneratePinyin（新增）

**文件**：新建 `backend-service/proto/evie/service/v1/enhancement.proto`（追加到 EnhancementService）

```protobuf
message GeneratePinyinRequest {
  string text = 1 [(buf.validate.field).string = {min_len: 1, max_len: 256}];
  bool include_initials = 2; // 是否同时返回拼音首字母
}

message GeneratePinyinResponse {
  string pinyin = 1;             // 全拼（空格分隔，如 "ke fu nin hao"）
  string pinyin_initial = 2;    // 拼音首字母（如 "kfnh"）
  string normalized_text = 3;    // 规范化后文本（去标点、空格归一）
}

// EnhancementService 追加：
rpc GeneratePinyin(GeneratePinyinRequest) returns (GeneratePinyinResponse) {
  option (google.api.http) = {
    post: "/evie/v1/pinyin:generate"
    body: "*"
  };
}
```

**biz 实现要点**：
- 使用 `github.com/mozillazg/go-pinyin` 库（成熟、CGO-free、纯 Go 实现）
- 词典：`pkg/pinyin/data/` 预置 GB2312 + 常用企业词
- 多租户隐私：本接口是「无状态工具」，不限租户——任何已登录用户可调用（用于前端表单辅助）

**Operation 常量**：`eviev1.OperationEnhancementServiceGeneratePinyin`

## 四、多租户隐私矩阵（必须覆盖的测试用例）

### 4.1 词库 scope × ctx 租户

| 词库 scope | ctx 租户 = owner | ctx 租户 = 其他租户 | platform 管理员 |
|-----------|:---:|:---:|:---:|
| PLATFORM (tenant_id=0) | ✅ 可见 | ✅ 可见 | ✅ 可见 |
| SYSTEM (tenant_id=sys) | ✅ 可见 | ✅ 可见 | ✅ 可见 |
| TENANT (tenant_id=A) | ✅ 可见 | ❌ 403 | ⚠️ 需 admin Operation |

### 4.2 关键测试 Case

| # | 用例 | 期望 |
|---|------|------|
| 1 | ctx=TenantA，词库 scope=PLATFORM，`GetDictionaryStats` | 200 |
| 2 | ctx=TenantB，词库 scope=PLATFORM 且 owner=TenantA，`GetDictionaryStats` | 200 |
| 3 | ctx=TenantA，词库 scope=TENANT 且 owner=TenantB，`GetDictionaryStats` | 403 |
| 4 | ctx=platform_admin，词库 scope=TENANT 且 owner=TenantA，`GetDictionaryStats` | 200（需 admin Operation）|
| 5 | ctx=TenantA，`ListRelationsByDictionary(dictionary_id=PLATFORM)`，返回的关系 entry 来自 TenantB | 返回，但 `related_tenant_id` 标注；尝试编辑则 403 |
| 6 | ctx=TenantA，未登录，`GetDictionaryStats` | 401 |
| 7 | ctx=TenantA，`GeneratePinyin("客服您好")` | 200（无租户限制）|

## 六、依赖与里程碑

### 6.1 实施顺序

```
M1: proto 文件落地（diff 到 dictionary.proto + enhancement.proto）
   ↓ buf lint + buf breaking 通过
   ↓ generate 生成 Go 代码
M2: biz 单测（多租户隐私矩阵 + 7 个核心 Case）
   ↓ seed_evie.go 注册 Operation
M3: 联调（前端用 mock 数据跑通 token 流程）
   ↓ 后端联调（HTTP 接口联调）
M4: 端到端（Frontend-A 信息架构重构 + 详情页/关系管理可用）
```

### 6.2 工作量估算

| 任务 | 工作量 | 备注 |
|------|:---:|------|
| proto diff + buf breaking | 0.5d | 4 个 RPC + 2 个 message 改动 |
| biz 实现（4 个 RPC）| 2-3d | 含 JOIN 与聚合查询 |
| 单测（多租户隐私矩阵）| 1d | 7 个核心 Case + 边界 |
| seed_evie.go 注册 | 0.5d | 3 个新 Operation 常量 |
| mock seed 数据补充 | 0.5d | 3 个 scope 各 1 词库供 E2E |
| 后端联调 | 1d | 与前端一起 |
| **Backend-0 合计** | **5-7d** | |

## 七、开放问题（需用户/架构组决策）

| # | 问题 | 建议 | 影响 |
|---|------|------|------|
| 1 | `hit_rate` 是否要纳入「词库健康度」统计？算法是按 `EnhancementLog` 时间窗还是全量？ | 先按近 7 天，1.0 上线后再考虑滑动窗口 | 影响健康度展示 |

| 5 | 是否要在 `GetDictionaryStats` 响应里加 `recent_activities` 数组（前 5 条最近活动）？ | 不建议，应是独立接口 `ListRecentActivities`（P1）| 保持接口内聚 |
