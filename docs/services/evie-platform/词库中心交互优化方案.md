# evie 词库中心交互优化方案（总览）

日期：2026-08-25
状态：📋 方案评审中
适用范围：evie 词库中心 7 个页面 + 词库中心工作台（新增）

> 本文档是 evie 词库中心交互优化的总览，沉淀通用设计模式可复用至其他产品服务模块（Geo Engine、AI Agent Management 等）。
> 通用规范已沉淀到 [.agents/DESIGN.md](../../.agents/DESIGN.md)（产品服务模块设计模式章节）。

## 一、用户痛点

| 痛点 | 具体表现 |
|------|---------|
| 功能体验复杂 | 7 个独立页面拍平；关系管理 3 级嵌套选择；表单 8 字段平铺 |
| 交互界面不满意 | Vben Admin 默认蓝/灰；空状态用 antd 默认 Empty；术语裸露无解释 |

## 二、核心优化方向

### 2.1 信息架构：工作台 + 上下文模式

**问题**：7 个同级页面（词库/词条/关系/分类/版本/冲突/变更记录）让人找不到北
**方案**：

```
/evie/dictionaries                              # 词库中心工作台（新增）
/evie/dictionaries/:dictionaryId                # 词库详情（tabs）
/evie/dictionaries/:dictionaryId/entries        # 词条（默认 tab）
/evie/dictionaries/:dictionaryId/relations      # 关系（在词库上下文里）
/evie/dictionaries/:dictionaryId/versions       # 版本
/evie/dictionaries/:dictionaryId/conflicts      # 冲突
/evie/dictionaries/:dictionaryId/logs           # 变更记录
/evie/categories                                # 分类（独立，全局资源）
```

**通用模式**（可复用到其他产品服务）：
- **工作台入口**：每个产品服务的根页面应是「决策中心」（我的资源 + 全局事件 + 健康度 + 快速入口），而不是「7 个子页面的导航大厅」
- **上下文导航**：子资源应在父资源详情内通过 tabs 组织，而不是独立路由
- **例外**：跨父资源的共享资源（如分类）才用独立路由

### 2.2 表单：基础/高级分组 + 智能默认值

**问题**：8 个字段平铺，普通用户被迫面对拼音首字母等高级字段
**方案**：
- 必填字段立等可用（3 个）：标准表达、分类、优先级
- 高级字段默认折叠：拼音、拼音首字母、规范化文本、描述
- 拼音自动从 standardText 计算（前端 `pinyin-pro` + 后端 `GeneratePinyin` 兜底）

**通用模式**：
- 表单字段分「基础」+「高级」两组；高级默认折叠
- 字段自动填充（如拼音从标准词推算），不让用户重复劳动
- 字段带示例占位符（「例：您好」「您好！」「您好。」）

### 2.3 设计语言：服务品牌而非平台默认

**问题**：evie 没有自己的视觉语言，完全 Vben 默认蓝
**方案**（细节见 [.agents/DESIGN.md](../../.agents/DESIGN.md)「产品服务模块的设计语言」章节）：
- 主色：evie 深靛蓝 `#1F4FCC`（区别于平台默认蓝）
- 业务色：scope 三色（PLATFORM 紫/SYSTEM 蓝/TENANT 绿），让多租户边界视觉化
- 字体：Plus Jakarta Sans + Inter + JetBrains Mono
- 圆角：12px（比 antd 默认 6px 更大，更现代）

**通用原则**：
- 每个产品服务应有自己的品牌色（避免所有页面都是平台蓝）
- 多租户 scope 应有统一视觉规范（颜色映射）
- 字体优先选有性格的（不要所有页面都用同一套字体）

### 2.4 术语与文案：用户视角

**问题**：standardText、pinyin、normalizedText 等裸字段名直接展示
**方案**：建立「evie 术语表」（中英文对照），所有 UI 文案走 i18n

| 当前（直译） | 优化后 |
|------------|--------|
| standardText | 标准表达 |
| normalizedText | 规范化文本 |
| pinyin / pinyinInitial | 全拼 / 拼音首字母 |
| scope: TENANT | 作用域：租户私有 |
| source: MANUAL | 来源：手动录入 |
| relationType: ALIAS |关系：别名 |

**通用原则**：
- 文案用用户视角（「删除」而不是「Delete」），让按钮词做动词
- 错误信息友好（「无法删除：仍有 5 条词条关联」而不是「Conflict409」）
- 多租户 scope 文案统一（PLATFORM = 平台共享、SYSTEM = 系统级、TENANT = 租户私有）

### 2.5 空状态与引导

**问题**：空状态用 antd 默认 Empty 组件
**方案**：
- 服务品牌插画（手绘风语音波纹）
- CTA 引导（「还没有词库，从模板开始 →」）
- 操作示例数据（一键试用）

**通用原则**：
- 空状态不是「暂无数据」，而是「行动邀请」（CTA + 示例）
- 不要让用户面对空白不知所措

## 三、实施切片（与后端联动）

### 3.1 Backend-0：P0 接口先行（5-7d）

详见 [9-词库中心交互优化-P0 接口设计](./development/9-词库中心交互优化-P0接口设计.md)：

| 接口 | 用途 |
|------|------|
| `GetDictionaryStats` | 词库详情页顶部统计 |
| `ListRelationsByDictionary` | 词库级别关系列表 |
| `DictionaryRelation` 字段补全 | 关系表格自然语言化 |
| `GeneratePinyin` | 拼音生成后端兜底 |

### 3.2 Frontend-A：信息架构 + 设计 token（与 Backend-1 并行）

- 多级路由 `/dictionaries/:id/*`
- 设计 token 落地（颜色、字体、间距、scope 徽章）
- 词库中心工作台（占位，使用 mock 数据）
- 词库详情页 tabs（占位）

### 3.3 Backend-1：工作台与健康度接口（与 Frontend-A 并行）

- `GetDashboardOverview`
- `ListRecentActivities`
- `GetVocabularyHealth`

### 3.4 Frontend-B：核心页改造（3-5d）

- 词库中心工作台（接入 Backend-1 接口）
- 词库详情页（接入 Backend-0 接口）
- 关系管理重构（接入 Backend-0 接口）
- 词条表单分组 + 空状态插画

### 3.5 P2 推后到下一迭代（用户决策 D3:B）

- 模板词库快速入口
- 导入向导

## 五、设计决策记录

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| 1 | 词库中心工作台是否必备 | ✅ 是 | 让用户有「决策中心」而非「导航大厅」 |
| 2 | 关系管理是否独立页面 | ❌ 否 | 进入词库详情 tabs | 关系是词条的子资源 |
| 3 | 多租户 scope 是否视觉化 | ✅ 是 | 颜色徽章 + 边界提示 | 减少跨租户误操作 |
| 4 | 拼音自动补全策略 | 前端 + 后端兜底 | D4:B 选择 | 一致性更好 |
| 5 | 导入向导/模板词库优先级 | P2 推后 | D3:B 选择 | 先把核心信息架构搞定 |
| 6 | 信息架构重构是否影响后端 | ✅ 是 | 4 个 P0 接口必需 | 联动规划见 3.1 |
