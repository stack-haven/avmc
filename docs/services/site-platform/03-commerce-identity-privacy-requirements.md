## 0. 我对你需求的理解复述（请核对）

| # | 你的要求 | 我的落地解释 | 核对 |
|---|---|---|---|
| U1 | 网站要补充「订单 + 物流 + 用户登录资料存储」 | 新增三个能力域：**身份**（账户/登录）、**交易**（购物车→结账→订单）、**履约**（配送/物流跟踪）；均属站点产品能力，不是平台中台能力 | ☐ |

## 1. 范围与非目标

### 在范围

1. 账户：注册/登录/退出/找回、个人资料、地址簿、我的订单；
2. 交易：服务端购物车（登录后）、结账、下单、订单查询与取消；
3. 履约：配送方式与费用、运单号与物流跟踪、配送通知；
4. 隐私：政策页、同意采集与留痕、Cookie 分类、数据主体请求（导出/删除/撤回）；
5. 运营侧：订单处理、发货、退款登记、物流商对接配置。

### 非目标（本期不做，避免范围爆掉）

- 库存中心/仓库管理/WMS（只做「可售状态 + 下单校验」）；
- 促销引擎（优惠券/满减/会员价），先留价格字段与扩展点；
- 发票/收据自动化（俄罗斯 54-ФЗ 财政化，见 §7 与 Q5）；
- 多仓/跨境清关；
- 订阅制、预售、分期（金融服务）；
- 站内 IM 客服。

## 2. 用户旅程与「登录门禁」唯一性

### 2.1 匿名优先旅程

```text
浏览（首页/目录/商品/知识库/物种）      → 零个人数据，零登录态
加入购物车                              → 写 localStorage，零个人数据
查看购物车 / 改数量 / 删除               → 仍匿名
【唯一门禁】点击「Оформить заказ」
        ├── 已有账户 → 登录（手机验证码 或 邮箱+密码）
        └── 无账户   → 注册（或游客下单，取决于 Q2）
结账：收货信息 → 配送方式 → 支付方式 → 确认
订单创建 → 支付 → 发货 → 物流跟踪 → 签收
后续：我的订单 / 地址簿复用（需登录）
```

### 2.2 门禁规则（硬性，前后端双向执行）

| # | 规则 |
|---|---|
| G1 | **结账前零个人数据**：不得出现登录墙、邮箱订阅弹窗、优惠换取联系方式、行为跟踪 SDK |
| G2 | 登录提示**只出现在**：点击结账按钮时、访问 `/account/*` 时、点击「我的订单」时 |
| G3 | 门禁是**提示 + 可继续**：登录页必须说明「登录后可保存地址、查看订单」；不得恐吓式文案（如「不登录将失去购物车」） |
| G4 | 未登录时购物车**不得丢**；登录成功后合并本地购物车 → 服务端购物车，合并规则显式（同商品累加、上限受库存/限购约束） |
| G5 | 免登录查单（若采用 Q3 方案 B）：订单号 + 手机/邮箱末四位，可查看该单状态，**不暴露其他订单** |
| G6 | 后端独立鉴权：不得依赖前端隐藏按钮（平台硬规则：权限控制必须在后端执行） |
| G7 | 游客（未登录）不得产生「我的订单」列表；只能凭单号查单 |
| G8 | 退出登录必须清空客户端凭证与用户态缓存，购物车可保留（匿名态） |

### 2.3 新增页面（前端）

| 页面 | 路由 | 门禁 | 说明 |
|---|---|---|---|
| 登录 | `/login` | 公开 | 支持回跳 `?redirect=`，仅允许站内相对路径（防开放重定向） |
| 注册 | `/register` | 公开 | 同意隐私政策 + 条款（默认不勾选） |
| 找回 | `/reset` | 公开 | 邮箱/手机验证码流程 |
| 结账 | `/checkout` | **登录或游客** | 送达信息、配送、支付、确认 |
| 结账完成 | `/checkout/success` | 凭单号 token | 不显示「支付成功」除非支付回调已确认 |
| 我的订单 | `/account/orders` | 必须登录 | 列表 + 详情 + 物流时间线 |
| 订单详情 | `/account/orders/[id]` | 必须登录 | 含发票/收据下载（后期） |
| 地址簿 | `/account/addresses` | 必须登录 | CRUD，默认地址 |

## 3. 隐私规则（本文件的核心交付）

### 3.1 数据分层采集表

| 层 | 触发时机 | 采集字段 | 目的 | 存储位置 | 保留期 | 可见范围 |
|---|---|---|---|---|---|---|
| **P0 浏览** | 全站匿名 | 无个人数据；仅必要 cookie（语言、购物车本地） | 基本功能 | 浏览器 | 会话/本地 | 无 |
| **P1 购物车（匿名）** | 加购 | 商品 id、数量（localStorage） | 购物车功能 | 浏览器 | 用户清除前 | 无 |
| **P2 结账联系** | 结账表单 | 姓名、手机、邮箱、收货地址（国家/城市/街道/门牌/邮编） | 履约与联系 | 站点 DB（RU 境内） | 订单存续 + 5 年 | 订单处理角色 |
| **P3 账户** | 注册 | 邮箱、手机、密码哈希、同意记录 | 身份与登录 | 站点 DB / 身份域 | 账户存续 + 法定期 | 本人 + 身份域管理员 |
| **P4 支付** | 支付 | **不经我方服务器**：仅保存 PSP 交易号、金额、状态 | 交易凭证 | 站点 DB（仅引用） | 5 年 | 财务角色 |
| **P5 履约** | 发货 | 收件人姓名/电话/地址、运单号 | 交付与跟踪 | 站点 DB + 承运商 | 5 年 | 履约角色 + 承运商 |

**禁止采集**：身份证/护照号、完整银行卡号/CVV、生物特征、健康信息、未成年人信息（不针对 <18 营销）。

### 3.2 十二条硬规则

| # | 规则 | 实现要求 |
|---|---|---|
| R1 | **同意必须是主动行为** | 复选框默认未勾选；不得「继续即视为同意」替代明示同意（可保留「继续浏览」仅用于必要 cookie） |
| R2 | **同意可留痕** | `ConsentRecord{subject, purpose, policy_version, granted_at, revoked_at, ip, user_agent, source_page}`；政策改版 → 版本号变化 → 需重新同意 |
| R3 | **目的限定** | 结账数据不得用于营销；营销需单独同意（且默认关） |
| R4 | **最小化** | 表单字段逐个说明用途；非必填字段明确标「可选」；不收「先生日祝福」这类无用途数据 |
| R5 | **提示在采集点** | 每个采集点旁有 1 行说明 + 政策链接（不是只在 footer 放一个链接） |
| R6 | **本地化存储** | 152-ФЗ：俄公民个人数据存储于俄境内（需法务确认部署区域；见 Q7） |
| R7 | **跨境默认禁止** | 日志/分析/邮件服务不得把 PII 传境外；确需跨境需单独同意与法务批准 |
| R8 | **脱敏与最小可见** | 运营列表默认掩码手机/邮箱；日志禁止打印 PII；导出需二次确认 + 审计 |
| R9 | **保留与删除** | 见 §3.1；到期自动清理；账户删除 → 匿名化订单关联（保留法定账务数据） |
| R10 | **数据主体权利** | 导出（JSON/CSV）、删除、撤回同意，均在 `/account/profile` 与 API 层实现，响应时限写入政策 |
| R11 | **Cookie 分类** | 必要（语言/购物车/会话）默认开；分析/广告默认关，未同意不加载任何第三方脚本 |
| R12 | **不前置** | 见 §2.2 G1/G2；任何新增采集点必须走本表评审并登记 |

### 3.3 隐私提示的出现位置（不是只放一个页面）

| 位置 | 内容 |
|---|---|
| 结账表单上方 | 一段说明：收集什么、为什么、保存多久、政策链接 |
| 注册/登录页 | 同意条款与政策的勾选（默认不勾选） |
| 首次进入（RU 常见要求） | Cookie 提示条：接受必要 / 管理偏好；**不阻塞浏览** |
| 页脚 | 隐私政策 / 用户协议 / 配送与支付 / Cookie 设置 |
| 账户设置 | 导出我的数据 / 删除账户 / 撤回同意 |
| 商品详情页（若后续有到货通知） | 邮箱用途单独说明（本期不做） |

### 3.4 合规待确认（需法务，不由 Agent 断言）

- 152-ФЗ 具体义务：Роскомнадзор 通知、本地化、跨境告知；
- 54-ФЗ 财政化（收据开具）由 PSP 还是我方承担 → 决定支付集成方式（Q5）；
- 消费者保护法：7 天/14 天退货规则适用（俄罗斯远程销售有明确规则）、退款时限；
- 保留期是否以 5 年为准（会计/税务惯例）→ Q6。

## 4. 订单与履约（提案，待确认）

### 4.1 订单状态机（提案）

```text
created ──支付成功──▶ paid ──开始配货──▶ processing ──发货──▶ shipped ──签收──▶ delivered
   │                    │                    │                     │
   │取消/超时            │退款                 │取消（未发货）        │退货流程
   ▼                    ▼                    ▼                     ▼
cancelled           refunded             cancelled            return_requested → returned/refunded
```

- 状态变更必须留 `order_event` 审计（谁、何时、从什么到什么、备注）；
- 公开可见状态需**面向用户的语言**（不是内部枚举），三语；
- 超时未支付自动取消（时限可配，建议 30 分钟；Q8）。

### 4.2 关键约束

| 项 | 规则 |
|---|---|
| 金额 | 一律 `minor + currency`；订单快照保存下单时的名称/单价/税，商品后续改价不影响历史订单 |
| 幂等 | 下单接口必须支持幂等键（`pkg/idempotency` 已有），防重复提交 |
| 并发 | 库存校验与扣减在同一事务；失败回滚且返回可读原因 |
| 权限 | 用户只能看自己的订单；运营按角色看；后端强制，前端不参与判断 |
| 取消 | 未支付可自助取消；已支付需走退款流程（人工或 PSP 自动） |

## 8. 安全要求（硬性）

| # | 要求 |
|---|---|
| S1 | 密码哈希使用平台已有实现（不自研）；不存明文、不存可逆加密 |
| S2 | 会话：短期 access + 可撤销 refresh；服务端存 refresh 哈希；退出即撤销 |
| S3 | 验证码：限流（手机号/IP/设备）、有效期、错误次数上限、人机校验 |
| S4 | 防开放重定向（`redirect` 白名单站内相对路径）、CSRF（cookie 模式时）、XSS（结构化块模型已规避 HTML） |
