# 多租户认证与会话安全设计

日期：2026-06-28  
状态：实施中  
范围：Ark Tech Platform 认证、登录安全和管理后台会话治理

## 1. 现状结论

当前认证能力已经具备：

- JWT Access Token 和 Refresh Token。
- Redis Token 状态校验，登出后令牌失效。
- 刷新令牌轮换。
- 用户和租户状态校验。
- 基于 Redis 的登录失败次数、时间窗口和临时锁定。

当前缺口：

- Token Redis key 以 `user_id` 为维度，同一用户新登录会使旧 Access Token 失效，无法支持多设备会话。
- 登录和刷新没有独立会话 ID，无法只强制下线一个设备。
- 没有在线会话列表、设备/IP 信息和最近活跃时间。
- 登录成功、失败、锁定没有持久化安全日志。
- 当前 Logout 按用户删除 Token，本质是“全部设备下线”，不是“退出当前会话”。

## 2. 目标模型

### 2.1 登录安全事件

`LoginLog` 记录每一次认证结果：

- `tenant_id`
- `user_id`
- `identity`
- `login_type`
- `result`
- `failure_reason`
- `ip`
- `user_agent`
- `trace_id`
- `session_id`
- `created_at`

约束：

- 只允许追加和查询。
- 普通租户只能查询本租户日志。
- 未知账号也记录，但错误响应不能泄露账号是否存在。
- 密码、验证码、Token 永不进入登录日志。

### 2.2 会话

每次登录生成独立 `session_id`，Access Token 和 Refresh Token 共享该会话 ID。

Redis 逻辑结构：

```text
auth:session:<session_id>                 -> 会话元数据
auth:session:<session_id>:access          -> 当前 Access Token 摘要/状态
auth:session:<session_id>:refresh         -> 当前 Refresh Token 摘要/状态
auth:user-sessions:<tenant_id>:<user_id>  -> 用户会话集合
auth:tenant-sessions:<tenant_id>          -> 租户会话集合
```

行为：

- 同一用户允许多个有效会话。
- 刷新 Token 只轮换当前会话的 Token，不创建新会话。
- 普通登出只撤销当前 `session_id`。
- 管理员可以撤销本租户指定会话。
- 用户停用、租户停用和密码重置可以撤销用户全部会话。
- 会话过期后索引可以惰性清理或由后台任务清理。

## 3. 权限边界

- 租户管理员只能查看和撤销本租户会话。
- 用户可以查看自己的会话并退出其他会话。
- 平台管理员跨租户查看必须使用平台身份和显式租户上下文。
- 会话不存在和跨租户访问统一返回 NotFound，避免泄露。

## 4. 实施顺序

### 阶段 A：登录安全日志

- LoginLog Proto、Ent、repository、usecase、service。
- 登录成功、失败、锁定记录。
- 登录日志管理端只读列表和详情。
- 多租户隔离、分页和筛选测试。

### 阶段 B：Token 会话化

- Access/Refresh Token 增加共享 `session_id`。
- Redis SessionStore 和用户/租户会话索引。
- 登录创建会话，刷新轮换当前会话，退出撤销当前会话。
- 保留“撤销用户全部会话”内部能力。

### 阶段 C：会话治理

- 当前用户会话列表。
- 租户会话管理列表。
- 单会话强制下线。
- 用户、租户停用和密码重置触发全部会话撤销。
- 管理端页面和真实多设备验证。

## 5. 验收标准

- 成功、密码错误和临时锁定都会生成登录日志。
- 登录日志不包含密码、验证码或 Token。
- 租户之间不能读取登录日志。
- 同一用户两个设备登录后两个 Access Token 均有效。
- 刷新一个会话不影响另一个会话。
- 退出当前会话不影响其他会话。
- 管理员强退指定会话后，该会话 Access/Refresh Token 均失效。
- 停用用户或租户后，其全部会话失效。

### 2026-06-28 Token 会话化

- `AuthToken` 从 `user_id` 单 Token key 升级为 `session_id` 会话级 Access/Refresh Token key。
- Access Token 和 Refresh Token 共享同一 `jti/session_id`，Token 轮换增加 nonce，确保同会话新旧 Token 可区分。
- 新增用户会话集合和租户会话集合索引；刷新会话时同步延长 Token、会话元数据和索引 TTL。
- 同一用户允许多个会话同时有效；刷新一个会话不会影响其他会话。
- 普通 Logout 改为只撤销当前 JWT 对应会话，保留按用户撤销全部会话的内部能力。
- 新增租户会话列表、我的会话列表和单会话强制下线 API。
- 用户停用、删除和密码修改后撤销该用户全部会话；租户停用或删除后撤销目标租户全部会话。
- 跨租户撤销统一返回 NotFound；Redis 故障保留真实错误，不伪装为资源不存在。
- 新增在线会话管理页面、筛选、当前会话标识、强制下线确认、中英文文案和 mock 菜单定义。
- 修复前端刷新接口路径、Refresh Token 提交、登录后 Refresh Token 存储和轮换后状态更新。
- 单元测试覆盖双会话并存、单会话刷新隔离、跨租户撤销拒绝、单会话撤销不影响其他会话。
- `go test ./pkg/auth ./app/platform/admin/...` 和前端 typecheck 通过。
- Redis 菜单、业务套餐、Casbin 和缓存同步已完成，系统菜单共 14 个。
- 真实双设备 HTTP 联调通过：同一用户两个 Session ID 不同且两个 Access Token 同时返回 200。
- 刷新设备 A 后 Session ID 保持不变，旧 A Token 返回 401，新 A Token 和设备 B Token 返回 200。

## 7. 发布兼容性

- 本次 Redis key 从用户级 Token 变更为会话级 Token。
- 升级后旧 `admin_uat_<user_id>`、`admin_urt_<user_id>` Token 不再通过会话校验，现有登录用户需要重新登录。
- 这是安全模型切换的预期一次性行为；正式发布时应提前通知，并在部署脚本中清理旧前缀键。
- 新旧服务实例不能长期混合运行，否则旧实例签发的用户级 Token 无法被新实例识别。
