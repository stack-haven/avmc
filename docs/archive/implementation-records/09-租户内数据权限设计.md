# 租户内数据权限设计

日期：2026-07-02
状态：首期实施
范围：`backend-service/app/platform/admin`

## 1. 目标与边界

菜单权限回答“用户能否执行某个操作”，数据权限回答“操作允许覆盖哪些租户内数据”。
租户隔离始终先于数据权限：任何数据范围都不能跨越 `tenant_id`。

首期把用户和组织成员列表作为受控资源。部门、岗位、项目和产品服务业务数据需要按相同解析结果逐步接入，不能因为角色已经存在 `data_scope` 字段就宣称自动生效。

字典和参数属于共享配置资源，不直接映射到负责人、成员、部门或操作人字段。它们不使用部门数据范围裁剪，而通过以下边界保护：

- 字典类型和字典项是当前租户共享配置，依赖 `tenant_id` 隔离和后端操作授权控制。
- 参数定义、指定租户参数读写是平台控制面资源，只允许平台身份访问。
- 当前租户参数读写是租户自助配置，依赖当前认证租户上下文和后端操作授权控制。

## 2. 数据模型

- `User.dept_id`：用户所属主部门，只能引用当前租户部门。
- `Role.data_scope`：角色数据范围，默认值为 `2`（仅本人）。
- `Role.dept_ids`：自定义范围选择的当前租户部门集合。
- 租户管理员角色由系统维护，始终具有当前租户全部数据范围，但不获得平台控制面权限。

数据范围枚举：

1. 全部数据。
2. 仅本人。
3. 本部门。
4. 本部门及全部下级部门。
5. 自定义部门。

## 3. 解析规则

- 用户多个启用角色的数据范围取并集。
- 任一角色为全部数据或租户管理员时，不再追加部门过滤。
- 除全部数据外，用户始终可以读取自己的成员记录。
- 未绑定角色、范围缺失、范围无效或找不到有效部门时按“仅本人”处理。
- 自定义部门 ID、用户主部门 ID 都必须在存储层验证当前租户归属。

首期在 repository 构造查询谓词，不依赖前端隐藏或客户端提交过滤条件。用户完整列表、
简单列表、详情和内部成员检索复用同一个范围解析入口，列表计数必须使用相同谓词。

## 4. 部门层级一致性

“本部门及下级”依赖 `Dept.ancestors`。创建部门时从父部门生成完整祖先链；移动部门时
必须在同一事务中更新当前部门和所有后代的祖先链。存在层级循环时拒绝更新。

删除部门要求不存在下级部门，且没有用户主部门或角色自定义数据范围引用。

## 5. 管理端交互

- 用户创建和编辑必须可选择一个主部门。
- 角色创建和编辑必须选择数据范围。
- 选择自定义范围时配置部门树；非自定义范围保存时允许保留空部门集合。
- 新角色默认“仅本人”，避免接口调用遗漏字段时意外获得全租户数据。
- 租户管理员角色不可通过公开角色接口修改。

## 6. 验收标准

- 仅本人角色只能看到本人。
- 本部门角色可以看到本人和同部门用户。
- 本部门及下级角色可以看到完整后代部门用户。
- 自定义范围角色只能看到本人和所选部门用户。
- 多角色范围按并集生效；全部数据优先。
- 用户或角色不能关联其他租户的部门。
- 用户列表数据与总数使用相同范围。
- 直接访问范围外用户详情返回资源不存在。
- 移动部门后，全部后代祖先链同步更新。
- 租户管理员不受租户内部门范围限制。

## 7. 后续实施

1. 将统一范围解析抽为可复用的 `DataScopeResolver`，继续接入部门、岗位等有明确组织归属的资源。
2. 为业务实体定义“本人字段”和“部门字段”的映射，不使用反射猜测字段。
3. 增加部门关联用户、角色自定义范围的删除保护。
4. 数据权限配置变更后撤销受影响角色用户会话，确保长会话及时刷新。
5. 补充不同数据范围角色的真实 HTTP 列表与详情验收。

## 9. 2026-07-17 扩展实施记录

- 数据权限解析从用户仓储抽为可复用能力。
- 项目管理接入数据权限：列表、计数和详情只返回负责人或成员落在可访问用户集合内的项目，更新和删除通过详情前置校验继承该边界。
- 操作日志和登录日志接入数据权限：非全部数据范围用户只能查看可访问用户集合内 `operator_id` 或 `user_id` 对应日志。
