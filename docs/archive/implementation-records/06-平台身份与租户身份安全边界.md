# 平台身份与租户身份安全边界

日期：2026-06-30
状态：生效
范围：`backend-service/app/platform/admin`

## 1. 问题与结论

底座存在两种不同权限域：

- 平台控制面：管理全局菜单、业务套餐、租户生命周期及租户套餐绑定。
- 租户数据面：管理当前租户的用户、角色、部门、岗位、项目、字典、日志和会话。

`super_admin` 只表示某个租户内的最高管理员，不能自动获得平台控制面权限。平台控制面必须同时满足：

1. 登录用户所属租户在数据库中被标记为平台租户。
2. 认证服务把可信的 `platform_operator=true` 声明签入访问令牌和刷新令牌。
3. Casbin 为该角色同步平台策略。
4. 统一中间件再次校验平台身份。

只满足角色、菜单、前端按钮可见性或请求参数中的目标租户 ID，均不能获得平台控制面权限。

## 2. 数据模型

`Tenant.is_platform` 是内部部署属性：

- 默认值为 `false`。
- 不进入租户公开 Proto，不允许通过租户创建或编辑 API 修改。
- 只允许受控的部署初始化或数据迁移流程维护。
- 当前演示数据中租户 1 为平台租户，其他租户为业务租户。

新建业务租户始终使用默认值 `false`，不能通过开通接口创建第二个平台租户。

## 3. 令牌与会话

登录和刷新令牌时，认证仓储从当前有效租户记录读取 `is_platform`，生成签名声明：

```text
platform_operator: true | false
```

约束：

- 不信任客户端提交的平台身份字段。
- 刷新令牌重新签发时再次读取数据库，不沿用可能过期的租户属性。
- 平台标记变更后必须撤销该租户现有会话并重新登录，避免旧令牌继续使用旧身份。

## 4. 控制面操作

以下操作只允许平台身份：

- 全局菜单的查询、创建、修改、删除和状态维护。
- 租户的查询、开通、修改、生命周期、状态和删除。
- 业务套餐及套餐版本的查询、发布、回滚和维护。
- 指定租户的套餐绑定、固定版本和有效菜单查询。

`GetCurrentTenantEffectiveMenus` 是当前租户自助读取接口，属于租户数据面，不要求平台身份。

## 5. 授权纵深

### 5.1 Casbin

- `SyncSuperAdmin`：只同步租户数据面策略。
- `SyncPlatformAdmin`：同步租户数据面和平台控制面策略。
- 每次同步先删除该角色在当前租户域的完整旧策略，再写入目标策略，避免历史平台授权残留。
- `cmd/policy` 默认同步租户管理员；只有显式传入 `-platform` 才同步平台策略。

### 5.2 中间件

统一平台控制面中间件位于认证授权之后、业务处理之前。即使 Casbin 配置错误地放行普通租户，缺少签名平台声明的请求仍返回 `403 PLATFORM_OPERATOR_REQUIRED`。

### 5.3 数据层

- 租户数据实体继续由 Ent privacy policy 注入和过滤 `tenant_id`。
- 系统上下文只允许内部受控编排使用，不能由 HTTP/gRPC 请求直接构造。
- 关联关系也必须验证租户归属；例如字典项不能引用其他租户的字典类型。

## 6. 部署与迁移

升级步骤：

1. 执行 Ent schema migration，新增 `tenants.is_platform`，默认值为 `false`。
2. 通过受控初始化将唯一的平台租户标记为 `true`。
3. 重新同步 Casbin：平台租户使用平台策略，业务租户使用租户策略。
4. 撤销平台租户全部旧会话，要求平台用户重新登录。
5. 验证普通业务租户访问租户列表、业务套餐和全局菜单接口均返回 403。

当前开发环境可执行带迁移的 mock 初始化完成前 3 步；服务部署流程仍需显式完成会话撤销。

## 7. 验收标准

- 普通租户 `super_admin` 不能访问任何平台控制面接口。
- 平台管理员可以访问控制面，同时保留本平台租户的数据面能力。
- 普通租户仍可读取当前租户有效菜单并管理本租户资源。
- 平台声明在访问令牌、刷新令牌和令牌轮换后保持一致。
- 将平台策略重新同步为租户策略后，不残留控制面授权。
- 所有租户域实体跨租户查询不可见，更新和删除表现为资源不存在。
- 跨租户外键关联在存储层被拒绝。

## 8. 租户管理员与成员生命周期

### 8.1 稳定身份

租户管理员不能只依赖可修改的角色名称识别。`Role.is_tenant_admin` 是内部稳定标记：

- 新租户开通时，初始化角色必须写入该标记。
- 迁移程序将历史名称严格等于“租户管理员”的角色回填为管理员角色。
- 公开角色接口只返回该标记，不允许客户端创建、修改或清除。
- 管理员角色禁止编辑、停用和删除，避免绕过用户侧保护。

名称不符合历史约定的自定义管理员角色不会被自动回填，升级前必须人工核对。

### 8.2 用户与角色

- 创建和修改用户时，角色 ID 必须属于当前租户且处于启用状态。
- 用户详情和列表返回角色 ID，前端通过用户详情完成授权回显。
- 普通角色菜单必须与租户当前业务套餐的有效菜单取交集。
- 租户管理员直接获得当前套餐的全部有效菜单，但不因此获得平台控制面权限。
- 密码或角色发生变化后撤销该用户全部会话，要求重新登录获取新权限。

### 8.3 最后管理员保护

删除用户、停用用户或移除管理员角色前，必须在事务内锁定目标用户，并按显式
`tenant_id` 统计当前租户仍启用的管理员。若目标用户是最后一名有效管理员，操作返回
`409 LAST_TENANT_ADMIN_REQUIRED`。

该校验不能只依赖隐式租户过滤。事务、系统上下文或隐私规则变化时，显式租户条件仍是
最后一道隔离边界。

### 8.4 Casbin 同步

- 用户获得租户管理员角色后，写入该租户域的 `super_admin` 成员关系。
- 用户失去管理员角色、被删除或停用后，删除对应成员关系。
- 全量策略同步必须清理已不存在或已失去资格的历史成员，避免残留授权。
- 新租户开通事务完成后，为初始化管理员建立成员关系。

数据库事务与 Casbin 存储当前不是同一个原子事务。同步失败时接口返回错误，权限缩减场景
会先撤销会话以阻止旧令牌继续访问；后续应使用事务消息或 outbox 将策略同步升级为可恢复
的一致性流程。

### 8.5 回归基线

- 跨租户角色不能绑定到当前租户用户。
- 两个租户同时存在时，一个租户的管理员不能参与另一个租户的最后管理员计数。
- 增加第二名管理员后，原管理员才允许被停用、删除或移除管理员角色。
- Casbin 撤销单个管理员时不能影响同租户其他管理员。
- 用户更新接口使用 ProtoJSON FieldMask 字符串，例如
  `"updateMask": "nickname,roleIds"`。
