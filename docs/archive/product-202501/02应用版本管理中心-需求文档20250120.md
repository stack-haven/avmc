# **应用版本管理中心-需求文档 v.1.0**

## **需求规划阶段**

## 1. **概述**

本系统旨在为多个应用项目提供统一的版本发布与管理平台，支持安卓和 iOS 应用的版本更新、灰度发布、更新推送、用户反馈收集等功能。系统支持多个项目管理，并提供灵活的用户权限控制。

## 2. **系统功能需求**

### 2.0 **项目管理**

#### 2.0.1 功能概述

-   提供项目的新增、编辑、删除功能。
-   支持管理员配置不同用户对项目的访问权限。

#### 2.0.2 主要功能

-   **项目新增**：允许管理员创建新项目，配置项目名称、描述、负责人等信息。
    -   项目名称（`project_name`）：字符串，必填，项目唯一标识。
    -   项目描述（`project_description`）：文本，可选，项目详细描述。
    -   项目负责人（`project_owner`）：用户ID，必选，负责人的用户ID。
    -   项目状态（`project_status`）：枚举，默认“启用”，可选“启用”、“禁用”、“维护中”。
    -   项目Logo（`project_logo`）：URL，可选，项目Logo图片链接。
-   **项目编辑**：允许管理员修改项目信息。
    -   项目名称（`project_name`）：字符串，必填，项目唯一标识。
    -   项目描述（`project_description`）：文本，可选，项目详细描述。
    -   项目负责人（`project_owner`）：用户ID，必选，负责人的用户ID。
    -   项目状态（`project_status`）：枚举，默认“启用”，可选“启用”、“禁用”、“维护中”。
    -   项目Logo（`project_logo`）：URL，可选，项目Logo图片链接。
-   **项目删除**：允许管理员删除项目。
    -   项目ID（`project_id`）：整型，必填，要删除的项目ID。
-   **权限管理**：允许管理员配置不同用户对项目的访问权限，包括管理员、开发者、运营等角色。
    -   用户ID（`user_id`）：整型，必填，要配置权限的用户ID。
    -   角色（`role`）：枚举，必选，可选“管理员”、“开发者”、“运营”。
    -   权限列表（`permissions`）：数组，可选，权限列表，例如["version_manage", "feedback_view"]。

### 2.1 **版本发布管理**

#### 2.1.1 功能概述

-   支持安卓 APK 文件和 iOS 应用的版本发布与管理。
-   提供版本发布的详细信息配置，包括版本号、更新内容、更新类型等。
-   支持强制更新和可选更新策略的配置。
-   支持灰度发布功能，逐步向指定用户群体推送更新。
-   **版本管理基于项目**

#### 2.1.2 主要功能

-   **项目选择**：允许管理员选择项目进行版本管理。
    -   项目ID（`project_id`）：整型，必选，要管理版本的项目ID。
-   **版本号管理**：允许指定每个版本的版本号和更新日志。
    -   版本号（`version_code`）：字符串，必填，版本号，例如"1.0.0"。
    -   版本名称（`version_name`）：字符串，必填，版本名称，例如"首次发布"。
    -   版本描述（`version_description`）：文本，可选，版本详细描述，支持Markdown格式。
    -   最低支持SDK版本（`version_min_sdk`）：整型，可选，最低支持的SDK版本。
    -   目标SDK版本（`version_target_sdk`）：整型，可选，目标SDK版本。
    -   应用包名（`version_package_name`）：字符串，必填，应用包名，例如"com.example.app"。
    -   构建版本号（`version_build_number`）：整型，可选，构建版本号，用于区分同一版本号的不同构建。
    -   发布说明（`version_release_notes`）：文本，可选，版本发布说明，支持富文本或Markdown格式。
    -   是否强制更新（`version_is_force_update`）：布尔值，默认为false，是否强制用户更新。
    -   是否静默更新（`version_is_silent_update`）：布尔值，默认为false，是否静默更新。
    -   下载链接（`version_download_url`）：URL，必填，下载链接地址，可以支持多个下载链接，使用JSON数组存储。
    -   文件大小（`version_file_size`）：整型，必填，文件大小，单位为字节。
    -   MD5校验值（`version_md5`）：字符串，可选，MD5校验值，用于校验文件完整性。
    -   SHA256校验值（`version_sha256`）：字符串，可选，SHA256校验值，用于校验文件完整性。
-   **强制更新设置**：可以设置强制更新的条件（如版本号差异、时间限制）。
-   **灰度发布控制**：支持按用户分组、设备类型、活跃度等策略进行灰度发布。
-   **版本历史记录**：系统存储版本发布历史，可以查看每个版本的发布详情。

### 2.1.1 **Release 发布管理**

#### 2.1.1 功能概述

-   提供 Release 版本的发布、更新、删除功能。
-   支持 Release 版本的灰度发布、全量发布。

#### 2.1.2 主要功能

-   **Release 发布**：允许管理员创建新 Release，配置 Release 名称、版本、发布说明等信息。
    -   Release名称（`release_name`）：字符串，必填，Release名称。
    -   Release版本（`release_version`）：字符串，必填，Release版本号。
    -   发布说明（`release_description`）：文本，可选，发布说明。
    -   发布类型（`release_type`）：枚举，必选，发布类型，可选“灰度发布”、“全量发布”。
    -   发布状态（`release_status`）：枚举，默认“草稿”，可选“草稿”、“待发布”、“已发布”、“已撤回”。
    -   发布开始时间（`release_start_time`）：时间戳，可选，发布开始时间。
    -   发布结束时间（`release_end_time`）：时间戳，可选，发布结束时间。
    -   覆盖用户总数（`release_total_users`）：整型，只读，覆盖用户总数。
    -   成功更新用户数（`release_success_users`）：整型，只读，成功更新用户数。
    -   更新失败用户数（`release_fail_users`）：整型，只读，更新失败用户数。
    -   取消更新用户数（`release_cancel_users`）：整型，只读，取消更新用户数。
    -   更新成功率（`release_update_rate`）：浮点型，只读，更新成功率。
    -   发布说明（`release_notes`）：文本，可选，发布说明，支持富文本或Markdown格式。
-   **Release 更新**：允许管理员修改 Release 信息。
    -   Release名称（`release_name`）：字符串，必填，Release名称。
    -   Release版本（`release_version`）：字符串，必填，Release版本号。
    -   发布说明（`release_description`）：文本，可选，发布说明。
    -   发布类型（`release_type`）：枚举，必选，发布类型，可选“灰度发布”、“全量发布”。
    -   发布状态（`release_status`）：枚举，默认“草稿”，可选“草稿”、“待发布”、“已发布”、“已撤回”。
    -   发布开始时间（`release_start_time`）：时间戳，可选，发布开始时间。
    -   发布结束时间（`release_end_time`）：时间戳，可选，发布结束时间。
    -   发布说明（`release_notes`）：文本，可选，发布说明，支持富文本或Markdown格式。
-   **Release 删除**：允许管理员删除 Release。
    -   Release ID（`release_id`）：整型，必填，要删除的Release ID。
-   **灰度发布**：允许管理员配置 Release 版本的灰度发布策略，逐步推送给用户。
    -   灰度发布策略（`gray_release_strategy`）：JSON，必填，灰度发布策略，例如{"percentage": 10, "user_ids": [1, 2, 3]}。
-   **全量发布**：允许管理员将 Release 版本全量发布给所有用户。
    -   Release ID（`release_id`）：整型，必填，要全量发布的Release ID。

### 2.2 **应用下载页配置与装修**

#### 2.2.1 功能概述

为每个应用提供可定制化的下载页，展示应用的基本信息、版本更新内容、运营推广信息等。

#### 2.2.2 主要功能

- **下载页模板设计**：支持模板化配置，可自定义页面布局、样式。
- **应用信息展示**：展示应用名称、简介、功能特点、版本更新信息。
- **推广内容管理**：展示营销活动信息，如优惠、折扣、活动公告等。
- **多版本展示**：支持展示多个版本的更新日志和下载链接。
- **图片/视频展示**：上传并展示应用截图、宣传视频等多媒体内容。
- **按钮配置**：支持自定义按钮（如下载、跳转到应用商店等）。

---

### 2.3 **客户端功能**

#### 2.3.1 功能概述

客户端实现版本检查、更新提示、更新执行等功能，确保用户能够方便地获取并安装最新版本。

#### 2.3.2 主要功能

- **版本检查**：在每次启动或定时检查新版本，获取最新版本号和更新信息。
- **更新提示**：
  - 可选更新：用户可以选择是否更新新版本。
  - 强制更新：用户必须更新才能继续使用应用。
- **灰度发布**：支持客户端根据灰度策略判断是否参与新版本推送。
- **更新后的引导**：更新完成后展示新功能介绍或使用引导。

---

### 2.4 **灰度发布管理**

#### 2.4.1 功能概述

通过灰度发布策略，逐步推送版本更新，确保新版本稳定。

#### 2.4.2 主要功能

- **用户分组**：支持按地区、设备、活跃度等条件将用户分组进行灰度发布。
- **推送控制**：支持动态调整灰度发布的用户范围。
- **反馈收集**：收集灰度发布用户的使用反馈，评估更新效果。
- **发布统计**：查看更新的进度、成功率等统计数据。

---

### 2.5 **用户反馈收集**

#### 2.5.1 功能概述

收集用户对应用的反馈，帮助开发团队改进应用质量。

#### 2.5.2 主要功能

- **反馈类型**：
  - Bug 报告：用户提交的崩溃或错误信息。
  - 建议/意见：用户对应用的建议或意见。
  - 评分与评论：用户对更新版本的评分和评论。
- **崩溃报告集成**：集成崩溃报告工具（如 Firebase Crashlytics、Sentry）自动捕获异常。
- **反馈管理**：通过后台系统查看和分析用户反馈，支持数据导出。

---

### 2.6 **版本控制与更新策略**

#### 2.6.1 功能概述

提供版本管理和更新策略配置，确保版本控制流程清晰。

#### 2.6.2 主要功能

- **版本信息存储**：系统存储每个版本的详细信息（版本号、更新内容、更新时间等）。
- **版本回滚**：支持在新版本出现问题时回滚到之前的版本。
- **版本检查 API**：客户端通过 API 获取最新版本号、更新内容、更新策略等信息。
- **协议更新 API**：管理隐私协议、服务条款等，并允许实时更新。

---

### 2.7 **基础信息管理（隐私协议、服务条款等）**

#### 2.7.1 功能概述

集中管理隐私协议、服务条款、免责声明和用户协议等法律性文件，确保应用符合合规要求。

#### 2.7.2 主要功能

- **协议内容管理**：存储和管理隐私协议、服务条款等协议内容。
- **协议版本控制**：记录协议的每个版本，并确保不同版本的用户看到相应的协议。
- **协议展示**：在用户安装或更新应用时，展示相关协议并强制用户同意。
- **合规性管理**：确保协议内容符合当地法律法规，如 GDPR 等。

---

### 2.8 **推送通知**

#### 2.8.1 功能概述

通过推送通知提醒用户进行版本更新，尤其是强制更新。

#### 2.8.2 主要功能

- **推送服务集成**：集成推送服务（如 FCM、OneSignal）发送版本更新通知。
- **定制化通知**：支持自定义推送内容（如更新公告、功能介绍等）。
- **引导更新**：通过推送通知引导用户点击更新按钮进行下载。

---

### 2.9 **后台管理与统计**

#### 2.9.1 功能概述

提供后台管理系统，便于运营人员查看版本更新状态、管理用户反馈及分析数据。

#### 2.9.2 主要功能

- **版本管理面板**：管理所有发布的版本，查看版本详情、更新日志等。
- **灰度发布管理**：查看灰度发布的用户群体、更新进度等。
- **用户反馈统计**：分析用户反馈，查看 Bug 报告、用户建议等。
- **更新效果分析**：查看更新后的崩溃率、活跃度、用户反馈等数据。

---

### 2.10 **用户管理功能**

#### 2.10.1 功能概述

提供灵活的用户权限管理，控制不同人员在系统中的操作权限。

#### 2.10.2 主要功能

- **角色管理**：支持创建不同角色并为每个角色配置不同的权限。
- **权限分配**：根据角色和任务类型分配用户权限，控制谁可以发布版本、管理反馈、修改协议等。
- **用户管理**：支持用户注册、登录、修改个人信息等功能。
- **操作日志**：记录所有操作日志，便于追踪和审计。

### 2.11 **多平台支持**

#### 2.11.1 功能概述

支持更多平台的应用更新，如 Windows、macOS 等桌面应用的版本管理和更新。

#### 2.11.2 主要功能

- **桌面应用更新**：支持 Windows、macOS 等桌面应用的版本发布与管理。
- **跨平台支持**：确保系统能够兼容不同平台的应用更新需求。

- 作为一名应用用户，我希望能够在更新后看到新功能的介绍，以便了解新版本的改进。

- 作为一名开发人员，我希望能够通过后台管理系统查看用户反馈和崩溃报告，以便快速修复问题。
- 作为一名开发人员，我希望能够管理和更新隐私协议和服务条款，以确保合规性。

### 高优先级

1. 版本发布管理
2. 灰度发布管理
3. 用户反馈收集
4. 基础信息管理（隐私协议、服务条款等）

### 中优先级

1. 应用下载页配置与装修
2. 客户端功能
3. 推送通知

### 低优先级

1. 后台管理与统计
2. 用户管理功能

## 5. **技术架构与实施**

- **前端技术**：使用 React/Vue 等前端框架构建管理后台，确保响应式设计和良好的用户体验。
- **后端技术**：基于 Spring Boot/Django 等框架提供高效的 API 服务，支持用户管理、版本发布、更新推送等核心功能。
- **数据库**：采用关系型数据库（如 MySQL）存储版本信息、用户数据、更新日志等。
- **文件存储**：使用云存储（如 AWS S3、阿里云 OSS 等）管理上传的 APK 文件、版本包等大文件。
- **推送服务**：集成推送服务如 FCM、OneSignal 等，确保版本更新通知能够及时送达用户。

---

### 6. **安全与合规性**

- **数据安全**：使用 HTTPS 协议保护数据传输，防止数据泄露。
- **用户数据保护**：确保符合 GDPR 等隐私保护法律要求，严格控制数据访问权限。
- **API 安全**：通过 OAuth2.0 或 JWT 进行 API 鉴权，确保只有授权用户能够执行敏感操作。

## 7. 验收标准

### 7.1 版本发布管理

1.  管理员可以成功发布新版本，填写版本信息并上传更新包。
    *   **验收步骤**：
        1.  管理员登录系统。
        2.  进入版本管理模块。
        3.  点击“新增版本”按钮。
        4.  填写版本信息并上传更新包。
        5.  点击“发布”按钮。
        6.  验证版本是否成功发布，包括数据库中是否新增版本记录，文件存储服务中是否成功上传更新包。
2.  用户可以接收到新版本的更新通知。
    *   **验收步骤**：
        1.  管理员发布新版本。
        2.  用户打开客户端。
        3.  验证用户是否收到更新通知，包括通知内容是否正确，点击通知是否能正确跳转到更新页面。

### 7.2 灰度发布管理

1.  管理员能够成功配置灰度发布策略，逐步推送新版本。
    *   **验收步骤**：
        1.  管理员登录系统。
        2.  进入灰度发布管理模块。
        3.  选择要灰度发布的新版本。
        4.  配置灰度发布策略，例如选择用户分组、设置推送比例。
        5.  点击“开始灰度发布”按钮。
        6.  验证灰度发布策略是否生效，例如查看用户分组是否正确，推送比例是否符合预期。

### 7.3 用户反馈收集

1.  用户能够提交反馈信息（Bug 报告、建议、评分等）。
    *   **验收步骤**：
        1.  用户打开客户端。
        2.  进入用户反馈模块。
        3.  填写反馈信息并提交。
        4.  验证反馈信息是否成功提交，包括数据库中是否新增反馈记录，管理员是否能够查看到反馈信息。

### 7.4 推送通知

1.  管理员能够成功配置并发送版本更新通知。

## 12. 部署需求

1.  **单机部署**：系统应支持单机部署，方便开发测试。
2.  **集群部署**：系统应支持集群部署，提高可用性和性能。
3.  **Docker 部署**：系统应支持 Docker 部署，简化部署流程。

## 13. 非功能性需求

1.  **性能需求**：
    *   系统在高并发情况下，响应时间应小于 2 秒。
    *   系统应支持至少 1000 个并发用户。
2.  **安全需求**：
    *   系统应使用 HTTPS 协议进行数据传输，防止数据泄露。
    *   系统应采用 OAuth2.0 或 JWT 进行 API 鉴权，确保只有授权用户能够执行敏感操作。
    *   系统应符合 GDPR 等隐私保护法律要求，严格控制数据访问权限。
3.  **可用性需求**：
    *   系统应具备高可用性，确保 99.9% 的时间可用。
    *   系统应支持自动故障恢复，确保在故障发生时能够快速恢复。
4.  **可维护性需求**：
    *   系统应采用模块化设计，方便维护和扩展。
    *   系统应提供详细的日志记录，方便问题排查。
