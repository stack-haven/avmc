# 应用版本管理中心服务产品需求总览

版本：v1.0  
日期：2026-06-03  
适用范围：项目开发底座内置的应用版本管理中心（AVMC）服务管理后台、后端 API、客户端版本检查能力、后续 AI 扩展能力

## 2. 产品目标

应用版本管理中心（AVMC）是项目开发底座上的一个业务服务，面向多项目应用的版本发布与运营管理，目标是统一管理多个应用项目的版本、Release、灰度发布、下载页、反馈、协议、用户权限和推送通知。

核心价值：

- 降低多应用版本维护成本。
- 提升版本发布、灰度验证和回滚效率。
- 建立用户反馈、更新统计、协议管理的闭环。
- 为后续 AI 辅助发布策略、反馈归类、故障预测保留扩展空间。

## 3. 用户角色

- 系统管理员：管理用户、角色、菜单、部门、项目权限和全局配置。
- 项目管理员：管理指定项目的版本、Release、灰度策略、下载页和推送。
- 开发人员：查看版本发布结果、用户反馈、崩溃/错误线索，参与问题修复。
- 运营人员：配置下载页、推广内容、推送通知、反馈处理状态。
- 客户端用户：接收版本检查结果、更新提示、协议展示和推送通知。

## 5. 核心模块需求

### 5.1 项目管理

目标：为不同应用提供独立的版本、下载页、协议、权限和统计边界。

主要能力：

- 创建、编辑、删除项目。
- 设置项目名称、描述、负责人、状态、Logo。
- 配置项目成员和角色权限。
- 项目状态至少包括启用、禁用、维护中。

关键字段：

- `project_id`
- `project_name`
- `project_description`
- `project_owner`
- `project_status`
- `project_logo`
- `permissions`

验收标准：

- 管理员可以创建项目，并在列表中查看。
- 项目名称唯一，重复时明确提示。
- 禁用或维护中的项目不能继续进行发布操作。
- 删除项目前应校验是否存在关联版本、Release 或下载页。

### 5.2 版本管理

目标：管理每个项目下的应用版本、更新包、更新说明和回滚能力。

主要能力：

- 创建、编辑、查看、删除版本。
- 支持整包更新与资源包更新。
- 支持强制更新、静默更新、可选更新。
- 支持上传更新包并记录文件大小、校验值和下载地址。
- 支持版本历史和回滚。

关键字段：

- `project_id`
- `version_code`
- `version_name`
- `version_description`
- `version_min_sdk`
- `version_target_sdk`
- `version_package_name`
- `version_build_number`
- `version_release_notes`
- `version_is_force_update`
- `version_is_silent_update`
- `version_download_url`
- `version_file_size`
- `version_md5`
- `version_sha256`
- `update_type`

验收标准：

- 管理员可以为指定项目创建版本并上传更新包。
- 版本号格式应校验，项目内版本号不应重复。
- 版本列表支持按项目、状态、发布时间筛选。
- 版本详情展示更新说明、文件信息、发布状态和历史记录。
- 回滚操作必须二次确认，并记录操作日志。

### 5.3 Release 发布管理

目标：把版本发布行为从版本资料中拆出，支持草稿、灰度、全量和撤回。

主要能力：

- 创建、编辑、删除 Release。
- 支持草稿、待发布、已发布、已撤回状态。
- 支持灰度发布和全量发布。
- 支持发布开始时间、结束时间和发布说明。
- 统计覆盖用户数、成功更新数、失败数、取消数和成功率。

关键字段：

- `release_id`
- `release_name`
- `release_version`
- `release_description`
- `release_type`
- `release_status`
- `release_start_time`
- `release_end_time`
- `release_total_users`
- `release_success_users`
- `release_fail_users`
- `release_cancel_users`
- `release_update_rate`
- `release_notes`
- `gray_release_strategy`

验收标准：

- 管理员可以基于指定版本创建 Release。
- 草稿状态可编辑，已发布状态不允许随意修改核心发布内容。
- 灰度发布必须绑定灰度策略。
- 全量发布必须明确确认。
- 撤回 Release 后客户端不应再获得该 Release 的更新结果。

### 5.4 灰度发布

目标：按用户、设备、地区、活跃度或百分比逐步发布版本，降低发布风险。

主要能力：

- 创建灰度策略。
- 支持百分比灰度、用户 ID 白名单、设备条件、地区条件。
- 支持逐步扩大灰度范围。
- 监控覆盖用户数、成功率、失败率、取消率、反馈数量。

关键字段：

- `gray_release_strategy`
- `percentage`
- `user_ids`
- `device_tags`
- `regions`
- `active_level`

验收标准：

- 管理员可以为 Release 配置灰度策略。
- 策略保存后客户端版本检查 API 能返回符合条件的更新结果。
- 调整灰度比例后，新请求按新策略生效。
- 灰度监控数据能辅助判断是否进入全量发布。

### 5.5 客户端版本检查

目标：为客户端提供稳定的版本检查、更新提示和协议展示数据。

主要能力：

- 客户端启动或定时请求版本检查 API。
- 返回最新可用版本、更新类型、是否强制、下载地址、更新说明。
- 支持灰度策略判断。
- 支持协议更新提示。

关键输入：

- `project_id`
- 当前版本号
- 平台
- 设备信息
- 用户 ID
- 地区或标签

验收标准：

- 无可用更新时返回明确的无更新状态。
- 有可选更新时返回更新说明和下载地址。
- 有强制更新时返回强制标记，客户端可据此阻止继续使用旧版本。
- 灰度外用户不应收到灰度 Release。

### 5.6 应用下载页

目标：为每个项目提供可配置、可预览、可发布的下载页。

主要能力：

- 下载页模板选择。
- 配置应用名称、简介、版本信息、下载链接、截图、视频、推广内容。
- 支持草稿、预览、发布。
- 支持 SEO 标题、关键词、描述。

关键字段：

- `page_name`
- `page_status`
- `template_id`
- `app_name`
- `version_info`
- `download_url`
- `promotion_content`
- `page_custom_css`
- `page_custom_js`
- `page_seo_title`
- `page_seo_keywords`
- `page_seo_description`

验收标准：

- 运营人员可以创建下载页草稿并预览。
- 发布后公开地址可访问。
- 下载按钮能跳转到正确下载地址。
- 不同项目的下载页互不影响。

### 5.7 用户反馈

目标：收集用户反馈、Bug 报告、评分和截图，支持开发与运营闭环处理。

主要能力：

- 反馈列表、详情、分类、状态管理。
- 支持 Bug、建议、评分、评论等类型。
- 支持截图或附件。
- 支持导出或统计。

关键字段：

- `feedback_id`
- `project_id`
- `user_id`
- `feedback_type`
- `feedback_content`
- `rating`
- `status`
- `attachments`
- `created_at`

验收标准：

- 用户反馈可被提交并在后台查看。
- 管理员可修改处理状态。
- 反馈可按项目、类型、状态、时间筛选。
- 反馈详情保留完整上下文。

### 5.8 协议管理

目标：集中管理隐私协议、服务条款、免责声明等合规文档。

主要能力：

- 创建、编辑、发布协议。
- 支持协议版本历史。
- 支持多项目、多语言。
- 支持用户重新同意最新协议。

关键字段：

- `protocol_id`
- `project_id`
- `protocol_type`
- `protocol_version`
- `language`
- `content`
- `status`
- `effective_time`

验收标准：

- 管理员可以发布新协议版本。
- 历史版本可查看但不可随意改写。
- 客户端能获取当前生效协议。
- 协议更新后客户端可提示用户重新同意。

### 5.9 用户与权限管理

目标：提供后台用户、角色、菜单、部门、项目权限管理能力。

主要能力：

- 用户新增、编辑、删除、禁用。
- 角色与权限分配。
- 菜单管理与权限标识。
- 部门管理。
- 项目级访问权限。

验收标准：

- 不同角色只能访问授权菜单和操作。
- 项目级权限限制能影响项目相关数据访问。
- 关键操作应记录操作日志。

### 5.10 推送通知

目标：通过推送服务提醒用户更新或接收活动公告。

主要能力：

- 配置推送内容。
- 选择推送范围。
- 支持全量、分组、灰度用户推送。
- 记录发送状态和成功率。

验收标准：

- 管理员可以创建推送任务。
- 推送内容、目标范围、发送时间可查看。
- 推送结果可统计。

## 6. 管理后台 UI 要求

底座管理后台使用 `frontend-service/apps/web-antd-admin`，优先遵循以下模式：

- 页面放在 `src/views/<module>`。
- 路由放在 `src/router/routes/modules`。
- 页面 schema 放在 `data.ts`。
- 表单抽屉放在 `modules/form.vue`。
- API 封装放在 `src/api/<domain>`。
- 可见文案使用 i18n key。
- CRUD 页面优先使用 `Page + useVbenVxeGrid + useVbenDrawer + useVbenForm`。

界面风格：

- 后台工具型、安静、紧凑。
- 优先表格、筛选、抽屉、详情面板、状态标签。
- 不做营销式 hero 或装饰性页面。
- 删除、发布、回滚、撤回必须确认。

## 7. 后端实现要求

后端使用当前代码事实来源：

- API 契约以 `backend-service/proto` 为源头。
- 生成代码位于 `backend-service/api`。
- 业务实现按 `service -> biz/usecase -> data/repo -> ent schema` 分层。
- 底座活跃服务为 `backend-service/app/platform/admin` 和 `backend-service/app/ai/service`；AVMC 业务服务后端落点待定义；`backend-service/app/version/service` 当前冻结，只作为迭代 3 服务边界复审候选。
- 不手工修改生成代码、Ent gen、Swagger UI bundle。

## 8. 非功能需求

- 安全：敏感接口必须鉴权，关键操作应校验权限。
- 合规：协议、隐私、用户数据处理需支持审计和版本追踪。
- 性能：列表接口支持分页、筛选和排序。
- 可维护性：模块边界清晰，公共能力复用现有 `pkg` 和 Vben packages。
- 可扩展性：保留多平台、AI、复杂灰度策略、多语言能力扩展空间。
- 可部署性：支持本地开发、Docker 和后续集群部署。

## 9. 当前不作为 MVP 的范围

- 完整 AI 自动发布决策。
- 复杂机器学习故障预测。
- 多云推送通道统一编排。
- 桌面应用完整自动更新器。
- 下载页高级低代码装修器。

## 10. 统一验收口径

每个模块进入开发前，应补齐：

- 后端 API 契约。
- 数据模型和权限规则。
- 前端列表、筛选、创建、编辑、详情、删除或状态操作。
- i18n 文案。
- 至少覆盖核心成功路径和关键失败路径的测试或手工验收步骤。
- 操作日志或审计需求。
