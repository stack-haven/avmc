# 租户管理人工测试完善需求

日期：2026-08-04  
状态：实现完成，完整回归待续  
优先级：P0  
适用范围：Ark Tech Platform 管理后台 `web-antd-admin`

## 一、背景与问题

租户管理基础能力完成重构后，人工测试发现以下体验和一致性问题：

1. 租户套餐的基础信息、能力配置和菜单权限集中在侧边抽屉中。菜单数量较多时，树形权限区空间不足、浏览困难，且基础信息修改与高影响权限变更混在同一操作中。
2. 租户列表的生命周期值与后端枚举序列化格式不一致，造成状态标签显示错误。
3. 新增和修改租户共用同一套三步流程，基础信息、初始管理员和套餐绑定的适用时机没有清楚区分。

## 二、目标

- 套餐基础信息与菜单权限独立管理，减少误操作并提高大规模菜单树的可读性。
- 生命周期状态按后端真实枚举稳定显示和提交。
- 新增租户时清楚完成基础信息、初始管理员、套餐绑定三个阶段；编辑租户时只展示基础信息和套餐绑定，不展示无法修改的初始管理员。
- 保持 Vben 管理后台的高密度工具型风格，同时具备清晰层级、响应式布局、键盘焦点和中英文文案。

## 三、范围内需求

### 3.1 套餐基础信息

- 基础信息抽屉只编辑名称、编码、排序、描述及已有能力配置。
- 菜单树不再出现在基础信息抽屉中。
- 新建套餐允许先保存基础信息，再通过独立入口配置菜单。
- 编辑基础信息时必须保留已有菜单 ID，不能因为表单中不展示菜单而清空权限。

### 3.2 套餐菜单权限独立配置

- 套餐列表提供明确的“菜单权限”操作入口。
- 使用宽版独立模态框承载菜单权限配置，不使用窄侧边抽屉。
- 顶部显示套餐名称、编码、已选菜单数量和操作说明。
- 支持按菜单名称搜索、全部展开/收起、全选/清空。
- 菜单树区域独立滚动，底部操作区保持可见。
- 保存菜单权限前显示变更结果；保存成功刷新套餐列表。
- 发布版本时复用已保存的菜单权限，只展示菜单数量摘要，不重复提供拥挤的多选框。

### 3.3 租户生命周期

- 前端兼容后端枚举字符串 `TENANT_LIFECYCLE_STATUS_*`，并兼容历史数字值。
- 列表、筛选器和生命周期修改弹窗使用同一组选项。
- 状态标签至少区分待开通、正常、已暂停、已到期和已注销。
- 生命周期修改属于高影响操作，提交前必须明确展示目标状态并要求确认。

### 3.4 租户新增与修改

- 新增租户采用三个清晰阶段：基础信息 → 初始管理员 → 套餐绑定。
- 编辑租户采用两个清晰分区：基础信息 → 套餐绑定。
- 初始管理员仅用于新租户原子开通，编辑时不展示该步骤。
- 每一步展示简短说明、完成状态和当前选择摘要。
- 套餐绑定使用可搜索多选，并展示已选套餐数量；空选择时给出明确提示。
- 一个租户可以同时绑定多个业务套餐；新增、编辑、提交和重新打开回显均不得退化为单套餐。
- 上一步、下一步、保存等动作名称与实际结果一致。

## 四、非目标

- 本轮不新增套餐、租户或生命周期后端 API。
- 本轮不改变租户生命周期状态机规则。
- 本轮不实现套餐计费、价格或订阅管理。
- 本轮不重建资源额度和缓存基础设施中的既有 TODO。

## 十、多套餐绑定回归补充（2026-08-04）

- 业务规则确认：租户与业务套餐保持多对多关系，前端选择器固定使用多选模式。
- 问题表现的直接原因是 FIX-01 导致保存请求返回 400，多选结果无法持久化；不是将控件改为单选，也不允许把业务规则收缩为单套餐。
- 编辑路径实测：同时选择套餐 1、2，界面显示“已选择 2 个套餐”，请求包含 `groupIds: [1,2]`，接口返回 200；刷新列表显示“2 个套餐”，重新打开编辑表单仍回显两项。
- 新增路径实测：完成基础信息和管理员步骤后，可连续选择两个套餐，界面显示“已选择 2 个套餐”；为避免产生测试租户，本次未提交创建请求。
- 体验补充：下拉提示明确说明支持多个套餐，选中标签使用响应式折叠，避免套餐较多时撑破抽屉宽度。

## 十一、租户管理员维护与密码重置

### 11.1 需求范围

- 租户列表为每个租户提供独立的“管理员”入口，不与租户基础信息、生命周期或套餐绑定混在同一表单。
- 管理员弹窗展示目标租户中绑定系统“租户管理员”角色的账号，并明确显示用户名、姓名、邮箱、手机号和账号状态。
- 允许平台管理员修改租户管理员的姓名、邮箱和手机号；用户名及系统维护的租户管理员角色在本入口中只读。
- 密码重置使用独立高风险操作：两次输入新密码、校验强度、二次确认，成功后撤销该管理员现有登录会话。
- 所有读取和写入必须由后端同时校验 `tenant_id`、`admin_user_id` 和租户管理员角色，禁止仅依赖前端传参或隐藏控件实现隔离。
- 支持一个租户存在多个管理员账号；管理员列表不得只假设初始管理员永久唯一。

### 11.2 非目标

- 本入口不新增或移除租户管理员角色，不替代租户内的完整用户/角色管理。
- 本入口不允许修改管理员所属租户、用户名、角色、部门或账号状态。
- 本轮不提供明文旧密码查看或找回能力。

### 11.3 交互结构

```text
┌──────────────── 租户管理员 · 某某租户 ────────────────┐
│ 管理员账号用于租户首次登录和权限治理                 │
├──────────────────────────────────────────────────────┤
│ admin      张三 · admin@example.com        [编辑资料] │
│ 租户管理员 · 已启用                         [重置密码] │
├──────────────────────────────────────────────────────┤
│                                              [关闭]  │
└──────────────────────────────────────────────────────┘
```

### 11.4 验收标准

| 编号 | 前置条件 | 操作 | 预期结果 | 验证方式 |
|------|----------|------|----------|----------|
| AC-12 | 租户已创建且存在管理员 | 从租户列表打开“管理员” | 只显示目标租户的租户管理员账号及只读身份信息 | API 测试 + 浏览器验证 |
| AC-13 | 管理员账号存在 | 修改姓名、邮箱或手机号并保存 | 数据保存成功，重新打开后正确回显；用户名和角色不可修改 | API 测试 + 浏览器验证 |
| AC-14 | 管理员账号存在 | 输入两次一致且合规的新密码并确认重置 | 密码以哈希保存，旧会话撤销，页面不回显明文密码 | 后端测试 + 浏览器验证 |

| AC-16 | 两次密码不一致或强度不足 | 尝试提交密码重置 | 前端阻止提交并给出明确修正提示 | 浏览器验证 |

### 11.5 2026-08-04 实现与验证记录

- 租户列表新增“管理员”独立入口，管理员资料编辑与密码重置采用两个独立操作，避免与租户基础信息、套餐绑定混杂。
- 管理员列表接口仅返回目标租户下具备租户管理员角色的账号；本地种子数据验证可正确展示同一租户的多个管理员。
- 管理员资料修改仅开放姓名、邮箱、手机号，用户名和租户管理员身份保持只读；空手机号可正常保存。
- 密码重置要求 8–72 位，并同时包含大小写字母、数字和特殊字符；两次输入不一致或强度不足时确认按钮不可用，提交前再次进行风险确认。
- 后端重置密码时使用密码哈希，并撤销该管理员已有登录会话；接口同时校验租户、账号归属和租户管理员角色。
- 自动化验证：租户业务层、数据层测试通过，服务层编译通过，前端类型检查通过。
- 浏览器验证：管理员入口、多人列表、资料编辑、弱密码拦截及合规密码放行均通过；验证过程中未实际执行密码重置，未改动现有账号密码。
- 当前状态保持 `[~]`：AC-14 的真实密码重置与会话撤销、AC-15 的跨租户拒绝仍需专门自动化用例或隔离测试账号完成验证后方可标记完成。
